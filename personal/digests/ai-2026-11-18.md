## 🏆 Repo of the Day

### ag-ui-protocol/ag-ui — standard protocol for wiring AI agents into frontend applications
**Link:** github.com/ag-ui-protocol/ag-ui | **Stars:** ~20.4k (↑ 2,773 this week) | **Language:** TypeScript / Python / .NET | **License:** MIT
**The problem:** Every agent framework handles token streaming, mid-response tool calls, shared state updates, human-in-the-loop pauses, and subagent lifecycles differently — so every frontend that talks to agents ships custom ad-hoc wiring that breaks on every framework upgrade.
**Why it's today's pick:** AG-UI 1.0 landed this week with a frozen, JSON-Schema-backed spec, and it's gaining real momentum (+2,773 stars this week from a base of ~17.6k). With Repo of the Day recently rotating through Claude Code orchestration tools, this is the protocol-layer piece that sits beneath them: once you emit AG-UI events from your agent backend, any AG-UI client — CopilotKit, Slack/Teams bots, terminal apps — renders it without custom code. Integrations with LangChain, CrewAI, Mastra, Pydantic AI, and Google ADK mean the frameworks already know how to speak it.
**Try it in 60 seconds:**
```bash
# Scaffold a minimal AG-UI app (needs OPENAI_API_KEY set)
npx create-ag-ui-app@latest

# Or install the client directly
npm install @ag-ui/client
# Python: pip install ag-ui-protocol
# .NET:   dotnet add package AGUI.Client
```
**Instead of:** Hand-rolling SSE event handling, tool-call rendering, and state-sync logic for each new agent backend you wire to a frontend — which breaks every time you swap frameworks or add subagents.
**Watch out for:** `create-ag-ui-app` scaffolds templates against OpenAI by default — you'll need to adjust the backend to point at your own agent endpoint. No formal GitHub release tags yet (the repo shows no Releases entries despite listing 5,500+ commits) — pin to a version hash in production and watch for the first tagged release.

**Source:** OpenAI Blog | **Date:** 2026-11-17 | **Link:** https://openai.com/index/introducing-gpt-6-2-astra-sol/

**TL;DR:** GPT-6.2 Astra costs $8/M input / $0.40/M cached / $40/M output — 20% cheaper input than GPT-6 Astra — while posting +5.2 on Agent's Last Exam and +9 on Terminal-Bench-Science vs GPT-6 Astra per OpenAI's internal evals; Claude Fable 5.2 still leads Artificial Analysis's third-party index at 65 vs Astra's 62.

The price reduction is automatic — existing calls that move to the new model ID get the lower price with no other changes. For caching-heavy workloads (long system prompts, repeated document context), the 60% cached-input discount on Astra is the most impactful number: at $0.40/M cached vs ~$1/M previously, long-context agent workflows running repeated passes on the same documents get substantially cheaper. Run a parallel benchmark on your actual workload before committing to the switch.
**Affects you if:** You use GPT-6/GPT-6.1 in the OpenAI API or Bedrock and want lower costs; you build long-context or caching-heavy agentic workloads where the 60% cached-input discount applies.

## API & SDK Changes

### [MEDIUM] Anthropic Linked Billing (beta) — let your customers pay Claude API costs from their own Claude org, with per-app spend caps
**Source:** Anthropic Platform Release Notes | **Date:** 2026-11-17 | **Link:** https://platform.claude.com/docs/en/release-notes/overview
**What changed:** Anthropic ships a beta feature that separates billing for end-user Claude usage in your app from your own API billing. When enabled, the customer's Claude organization — not yours — is charged for the tokens their users consume in your app.
**TL;DR:** Send the `user-profiles-billing-2026-10-01` beta header plus a `billing_policy` field on each `/v1/messages` request; your customers pay their own Claude orgs for usage in your product, and they can set per-app spend caps or unlink anytime from the Claude Console.
**Developer signal:** To use it: (1) Add beta header `user-profiles-billing-2026-10-01` to API calls. (2) Set `billing_policy` on each `/v1/messages` or `/v1/chat/completions` request to control who pays. For this to work, the end user's organization must pay Anthropic directly for API usage — it does not work for customers on Claude.ai individual or Team plans. This directly unblocks a common B2B SaaS pattern: instead of your app absorbing Claude API costs and passing them on through your own pricing, enterprise customers can connect their own Claude org and pay directly. Customers can set a per-app spend cap in their Claude Console, unlink at any time, and control cost visibility on their end. If you're building Claude-powered enterprise tooling, this is the architecture that removes Claude API costs from your COGS line.
**Affects you if:** You build B2B SaaS or enterprise tooling on Claude where customers are paying Anthropic directly for API access; you want to shift Claude API costs to your enterprise customers' own accounts rather than absorbing them into your own billing.
**Adoption effort:** Moderate (add beta header and `billing_policy` field to API calls; your customers need direct Anthropic API billing relationships).
**Primary source:** https://platform.claude.com/docs/en/release-notes/overview (Nov 17 entry)

### [NOTABLE] Claude Code v2.1.327 — MCP server JSON via stdin, VS Code right-click, ExitWorktree safety check, 100 bug fixes
**Source:** Claude Code Changelog | **Date:** 2026-11-17 | **Link:** https://code.claude.com/docs/en/changelog
**What changed:** v2.1.327 adds `claude mcp add-json <name> -` (reads server config from stdin so API tokens never touch the command line), `/tui classic` as an alias for the non-fullscreen renderer, a VS Code Explorer right-click option "Claude Code: Add to Chat," and a confirmation step in `ExitWorktree` before removing a worktree that may hold unsaved work. Auto mode now ignores allow rules of the form `Bash(pnpm dlx *)` and similar. 100 bug fixes, including: Remote Control no longer deletes git-ignored files (like `.env`) when the server stops in worktree mode; `claude mcp add --scope project` stops instead of overwriting `.mcp.json` without an `mcpServers` key.
**TL;DR:** Claude Code v2.1.327 ships a security improvement for MCP onboarding (stdin for server JSON keeps tokens off command-line history), a data-safety guard for worktrees, and 100 bug fixes.
**Developer signal:** (1) **MCP onboarding**: if you're adding MCP servers with API keys, switch to `claude mcp add-json myserver - <<EOF ... EOF` to avoid leaking tokens into shell history or audit logs. The old `--json` flag still works but is now less necessary. (2) **Worktree safety**: `ExitWorktree` now prompts before removing a worktree that might have unsaved changes — if you use worktrees in unattended pipelines, check that the prompt doesn't block automation (the `--yes` flag or `autoApprove` may be needed). (3) **Remote Control + worktrees**: the fix for Remote Control not deleting `.env` files in worktree mode is real — if you use Remote Control with worktree isolation and had credential files vanishing on session end, upgrade now.
**Affects you if:** You onboard MCP servers with API keys; you use Claude Code's worktree mode in CI or unattended pipelines; you use Remote Control with worktrees.
**Adoption effort:** Quick (drop-in version upgrade; check worktree pipelines for new confirmation prompt if running unattended).
**Primary source:** https://code.claude.com/docs/en/changelog (v2.1.327, Nov 17 entry — fetched directly)
