## 🏆 Repo of the Day

### vercel-labs/agent-desktop — MCP-native desktop UI automation for AI agents, via accessibility tree

**Link:** github.com/vercel-labs/agent-desktop | **Stars:** ~20,340 (↑ 13,712 this week) | **Language:** Rust | **License:** Apache-2.0
**The problem:** Agents that need to operate desktop apps (macOS, Windows, Linux) have historically had to rely on screenshot-and-pixel matching — which is brittle, slow, and fails under system themes or resolution changes. agent-desktop reads the platform accessibility tree instead, so each UI element gets a stable `ref` that the agent acts on, re-reads, and verifies.
**Why it's today's pick:** v1.2.0 (Nov 5) added `agent-desktop mcp`, turning every command into an MCP tool over stdio — which means Claude Code, Codex, Gemini CLI, and any MCP-capable agent framework can now drive desktop UIs natively, without bespoke screen-capture scaffolding. The star surge (+13,712 this week) tracks directly with today's Claude Fable 5.2 launch: Fable 5.2 makes computer use a first-class capability with updated tooling requirements, and developers building computer-use agents are actively looking for a better execution substrate than screenshots. agent-desktop has 336 commits, v1.0.0 launched Oct 28, and it already ships Homebrew, npm, Cargo, and native archive releases for all three platforms.
**Try it in 60 seconds:**
```bash
# Install via npm (or Homebrew: brew install vercel-labs/agent-desktop/agent-desktop)
npm install -g agent-desktop

# Check platform permissions
agent-desktop status
agent-desktop permissions --guide  # walks you through Accessibility grant on macOS

# Start the MCP server (connects to Claude Code or any MCP client)
agent-desktop mcp

# Take a snapshot of your desktop to see all accessible elements
agent-desktop snapshot

# Get built-in agent skill instructions
agent-desktop skills get desktop
```
**Instead of:** Screen-capture pipelines (screenshot → OCR → click on pixel coords) — which break on retina displays, dark mode, overlapping windows, and app redraws. agent-desktop gives each element a ref and verifies actions by re-reading the tree.
**Watch out for:** macOS requires explicit Accessibility permission (System Settings → Privacy & Security → Accessibility) — without it, `snapshot` returns an empty tree. Linux requires AT-SPI2 on X11/Wayland (Ubuntu 24.04+). Ref IDs are snapshot-scoped: a stale ref from a previous snapshot returns an error and requires a fresh call.

## [BREAKING] Breaking Changes

### [BREAKING] Claude Fable 5.2 / Mythos 5.2: computer use toolset, prefix check, advisor model restrictions
**Source:** Anthropic Platform Release Notes | **Date:** 2026-11-09 | **Link:** https://platform.claude.com/docs/en/release-notes/overview
**What changed:** Three breaking API behaviors enforced simultaneously with Fable 5.2 / Mythos 5.2 launch:
1. **Computer use toolset:** `computer_20251124` returns a 400 error on Fable 5.2 / Mythos 5.2 (Bedrock excluded until further notice). Migrate to `computer_toolset_20260801`.
2. **Prefix check on thinking blocks:** If you edit the `system` prompt, `tools`, or an earlier message and re-send a Fable 5.2 / Mythos 5.2 thinking block from a later turn, the request returns a 400 error.
3. **Advisor tool model restriction:** A Fable 5.2 / Mythos 5.2 executor only accepts Fable 5.2 / Mythos 5.2 as its advisor. Any other model returns a 400 error.

**TL;DR:** Three new 400-error conditions for Fable 5.2 / Mythos 5.2 — computer-use toolset name changed, thinking-block reuse across edited conversations disallowed, advisor model restricted.
**Developer signal:** Update computer-use declarations to `computer_toolset_20260801` immediately if you are building computer-use agents targeting Fable 5.2. This is a string change in your tool declaration, not a code rewrite — but the old value hard-errors, not silently degrades. The prefix-check change affects multi-turn conversation management: if your agent loop modifies an earlier message (system prompt swaps, tool list changes) and then continues a conversation that includes thinking blocks, those thinking blocks must be from a new Fable 5.2 / Mythos 5.2 turn, not carried over. The advisor model restriction only affects systems using the Advisor tool (beta) pattern.
**Affects you if:** You build computer-use agents targeting Claude Fable 5.2 (or any future 5.x model); you manage multi-turn conversations with thinking blocks across system-prompt or tool-list changes; you use the Advisor tool beta.
**Adoption effort:** Quick (computer toolset: string rename) / Moderate (prefix check: depends on your conversation-management architecture)
**Primary source:** https://platform.claude.com/docs/en/release-notes/overview
