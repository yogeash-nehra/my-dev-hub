## 🏆 Repo of the Day

### max-sixty/worktrunk — git worktrees that actually work for parallel AI agents
**Link:** github.com/max-sixty/worktrunk | **Stars:** ~12.7k (↑ ~4.5k since Sept) | **Language:** Rust | **License:** Apache-2.0 / MIT

**The problem:** Running parallel coding agents in a single git checkout means agents overwrite each other's in-progress edits; raw `git worktree add` takes three commands and forces you to retype the branch name every time.

**Why it's today's pick:** With MCP Skills and Claude Code's parallel agent features maturing fast, worktree management is the next friction point in multi-agent workflows. Worktrunk removes it cleanly: one command creates a branch + worktree and optionally launches your agent (`wt switch -x claude -c feature-a -- 'Add user auth'`). The 12.7k stars reflect a growth curve that bent sharply upward in early-mid 2026 as parallel agent patterns went mainstream — not a one-day spike. It supports Claude Code, Codex, Gemini CLI and other agents, and ships on Homebrew, Cargo, winget, Conda and pacman.

**Try it in 60 seconds:**
```bash
brew install worktrunk   # or: cargo install worktrunk
wt config shell install  # enables directory switching

# Create a worktree + branch and launch Claude Code in it
wt switch -x claude -c feature-auth -- 'Add user authentication to the API'

# See all active worktrees with status
wt list
```
**Instead of:** Three `git worktree add` / `cd` / `git checkout` commands every time you want to spin up an agent on a new feature, then manually managing the cleanup.
**Watch out for:** No tagged releases yet (Releases section is empty); you're tracking the latest build. Merge automation (`wt merge main`) does squash + rebase under the hood — review its behavior in repos with strict history policies before relying on it.

## [BREAKING] Breaking Changes

### [BREAKING] Claude Code v2.1.332 — four silent breakages on GCP, Foundry, OTEL, and OAuth proxies
**Source:** Claude Code Changelog | **Date:** 2026-11-25 | **Link:** https://code.claude.com/docs/en/changelog

**What changed:** Four unrelated breaking changes shipped in a single release; none requires a major code rewrite, but each breaks a specific environment silently if not addressed.

**TL;DR:** `sonnet` on GCP Agent Platform and Foundry now means Sonnet 5.5; Foundry's default model is now Sonnet 5.5; OTEL `service.name` for desktop Code tab sessions changed to `claude-code-desktop`; and OAuth token proxy rules must now also match the `oat02-` prefix.

**Developer signal:**
1. **GCP Agent Platform + Foundry model aliases** — `sonnet` now resolves to Sonnet 5.5 on both platforms (was Sonnet 4.5/4.6). Foundry's `opus` alias now resolves to Opus 5.5. If you're pinning to a model family name rather than a specific version, your workloads will shift to a newer model on next restart. Deploy `claude-sonnet-5-5` and `claude-opus-5-5` explicitly on Foundry if they aren't already deployed; on GCP, update `VERTEX_REGION_CLAUDE_5_5_SONNET` if you hadn't set it yet (the old `4_5` variable is now a fallback, not the primary).
2. **Foundry default model** — if no model is configured, new Foundry sessions start on Sonnet 5.5 instead of Sonnet 4.5. Set `ANTHROPIC_DEFAULT_SONNET_MODEL` to lock the version if you need the old behavior.
3. **OTEL service name** — `claude-code-desktop` now appears in the `service.name` span attribute for desktop Code tab sessions, replacing the old `claude-code` default. Update any dashboards, alert rules, or cost-attribution queries that filter on `service.name = "claude-code"`. To preserve the old name set `OTEL_SERVICE_NAME=claude-code`.
4. **OAuth token prefix** — `CLAUDE_CODE_OAUTH_TOKEN` can now begin with `oat02-` in addition to `oat01-`. Any proxy rule or log-scrubbing pattern that only matches `oat01-` now misses valid tokens. Update regex rules to `oat0[12]-` and ensure the whole token value is masked, not just the prefix.
5. **Bonus** — `computer-use` is now a reserved skill name on Macs with computer use enabled. If you authored an MCP skill or command named `computer-use`, rename it; Claude Code will refuse to load it and shows a startup notice.

**Affects you if:** You run Claude Code terminal sessions on GCP Agent Platform or Microsoft Foundry; you have OTEL instrumentation configured; you run a proxy or gateway that filters or scrubs OAuth tokens; you have an MCP skill named `computer-use` on macOS.
**Adoption effort:** Quick (update model aliases and env vars) to Moderate (audit OTEL dashboards and proxy rules).
**Primary source:** https://code.claude.com/docs/en/changelog (v2.1.332, Nov 25 entry — fetched directly)

### [MEDIUM] Claude Code v2.1.332 — MCP skills in the `/` menu, PreSkillShellCommand hook, 93 fixes
**Source:** Claude Code Changelog | **Date:** 2026-11-25 | **Link:** https://code.claude.com/docs/en/changelog

**What changed:** MCP server skills appear in the `/` menu as `server:skill` (beta). A new `PreSkillShellCommand` hook can inspect and refuse a skill's inline shell commands as the skill loads. Computer use on macOS was updated to newer safety rules (some actions refused; typing speed reduced). 93 bug fixes and 19 improvements covering freezes, memory leaks, and cloud provider model resolution.

**TL;DR:** Claude Code now surfaces MCP skills directly in the slash-command menu, adds a hook to gate skill shell commands before they run, and ships 93 fixes targeting freezes (hooks with runaway output, MCP servers flooding stdout, named-pipe hangs) and cloud-provider model routing errors.

**Developer signal:** (1) **MCP skills** — if you have Claude Code 2.1.332+ and an MCP server that publishes skills, they now appear in `/` without any additional config. Install via `claude update` or your package manager. (2) **PreSkillShellCommand hook** — use this in `.claude/settings.json` to audit or block shell commands that skills execute inline, before they run. This is the right place to enforce sandboxing policies on third-party skills. Note: naming this hook in a settings file on v2.1.331 or older opens a startup dialog; upgrade before deploying a config that uses it. (3) **Computer use on macOS** — if you use computer use in your workflows, test after upgrading: some actions are now refused, and keyboard typing is slower due to new safety rules. Update any timing or action-sequence logic that depends on typing speed. (4) **Memory and freeze fixes** — the 93 fixes cover MCP server stdout flooding, named pipes (`.env` mounted by locked secrets managers), hooks with large output, and many VS Code reliability issues. Upgrading on a Windows enterprise machine is now materially safer (stability fix for company PCs that exited silently at startup).

**Affects you if:** You use MCP servers that publish skills; you run computer use workflows on macOS; you hook into skill or command execution; you're on Windows with Claude Code in a corporate environment.
**Adoption effort:** Quick (run `claude update`; review the breaking changes from the [BREAKING] entry above before upgrading on GCP/Foundry/OTEL setups).
