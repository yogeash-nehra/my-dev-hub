## [BREAKING] Breaking Changes

### [BREAKING] Pydantic AI v2.74.0 — PlaywrightBrowser drops WebRTC/WebSocket under egress policy; Gemini streaming usage counts change
**Source:** Pydantic AI | **Date:** 2026-11-24 | **Link:** https://github.com/pydantic/pydantic-ai/releases/tag/v2.74.0

**What changed:** Under any enforced egress policy, `PlaywrightBrowser` pages no longer expose `RTCPeerConnection`, `WebTransport`, `WebSocketStream`, or `FedCM`. Streaming Gemini responses routed through `OpenAIChatModel` now report final usage totals rather than a running sum, lowering reported token counts. ElevenLabs realtime session credentials are no longer recorded in trace spans.

**TL;DR:** Five security advisories fixed for `PlaywrightBrowser`; WebRTC and WebSocket browser transports are disabled under egress enforcement; Gemini streaming through `OpenAIChatModel` token usage figures drop (now correct).

**Developer signal:**
1. **WebRTC/WebSocket removal under egress policy:** If your agent uses a `PlaywrightBrowser` and your environment enforces egress policies (e.g., `pydantic-ai-harness` ≥ 0.74.0), any page that relied on `RTCPeerConnection`, `WebTransport`, `WebSocketStream`, or `FedCM` will silently fail — the browser APIs are simply absent. Audit your harness configuration and test affected pages. If you need these transports, you'll need to either disable egress enforcement for that sandbox or refactor to use `sandbox.commands.run()` for the network calls.
2. **Gemini streaming usage:** If you have cost-accounting or `UsageLimits` checks based on `OpenAIChatModel` streaming usage counts for Gemini, your figures will drop to reflect actual final usage. Budgets set against the inflated running-sum numbers will now have more headroom — verify your `UsageLimits` thresholds still make sense at the new (lower, correct) values.
3. **ElevenLabs traces:** If you export traces that included ElevenLabs session data, those credentials are no longer recorded from v2.74.0 onward — a good-news break if you weren't scrubbing them manually. Audit existing trace exports for older sessions.
4. **GPT-6.2 static instructions:** Static instructions are now sent as leading input messages on GPT-6.2 (changed from system-role format). If your agent prompt structure assumes GPT-6.2 receives instructions in a specific message position, test for behavioral regressions.

**Affects you if:** You build agents with `pydantic-ai`'s browser harness; you use `OpenAIChatModel` to route Gemini calls; you have `UsageLimits` tied to streaming Gemini token counts; you use ElevenLabs realtime sessions with tracing enabled.
**Adoption effort:** Moderate (audit egress policy + browser transport usage, verify token thresholds).
**Primary source:** https://github.com/pydantic/pydantic-ai/releases/tag/v2.74.0

### [BREAKING] Pydantic AI v2.75.0 — workspace authority enforcement cuts RepoContext/Skills/Memory instructions
**Source:** Pydantic AI | **Date:** 2026-11-25 | **Link:** https://github.com/pydantic/pydantic-ai/releases/tag/v2.75.0

**What changed:** Workspace files stored below `'operator'` authority are no longer included in instructions generated by `RepoContext`, `Skills`, and `Memory`. Gemini thinking tokens are now counted as output in `OpenAIChatModel` usage, so token counts and costs rise and `UsageLimits` can trip sooner.

**TL;DR:** Workspace-level files must now be at `'operator'` authority to appear in `RepoContext`/`Skills`/`Memory` instructions; Gemini thinking tokens now count toward output usage.

**Developer signal:**
1. **Authority enforcement:** If your workspace stores configuration, context, or instruction files at a user or sub-operator authority level and you rely on them appearing in `RepoContext`, `Skills`, or `Memory` output, those files will now be silently excluded. Audit your workspace file authority levels and promote any that should be visible to agents to `'operator'` authority.
2. **Gemini thinking token costs:** Any `UsageLimits` or cost-tracking code that budgets Gemini requests through `OpenAIChatModel` will now see higher output token counts (thinking tokens are added). If you have tight budget limits, increase them to account for the now-visible thinking overhead, or disable thinking for cost-sensitive runs.
3. **FallbackModel behavior:** `FallbackModel` and `ModelFallback` now trigger on empty or unreadable model responses, not just errors. If you have fallback chains and your primary model occasionally returns empty responses that you were ignoring, those will now trigger a fallback — test for unintended fallback activation.

**Affects you if:** You use `RepoContext`, `Skills`, or `Memory` with workspace files at non-operator authority; you use `OpenAIChatModel` to route Gemini calls with thinking enabled; you have `FallbackModel` chains.
**Adoption effort:** Moderate (authority audit + UsageLimits recalibration).
**Primary source:** https://github.com/pydantic/pydantic-ai/releases/tag/v2.75.0
*Quality gate score: 9 (official pydantic-ai release +3; concrete authority change with named components +2; primary source GitHub +2; within 24h +1; technical audience +1)*

## API & SDK Changes

### [HIGH] E2B ships `e2b-acp` v0.1.0 + resizable sandbox memory + port-forward CLI
**Source:** E2B (GitHub releases) | **Date:** 2026-11-26 | **Link:** https://github.com/e2b-dev/E2B/releases

**What changed:** E2B shipped two separate release batches today. Morning (12:35 UTC): introduced `@e2b/acp-python@0.1.0` for running Agent Client Protocol agents inside E2B sandboxes, added `Template.getInfo()` and `Template.listBuilds()`, deprecated all `sandbox.git` methods, and added `e2b sandbox port-forward`. Afternoon (16:28 UTC): added resizable memory — templates can be built with a maximum memory size, sandboxes can choose memory on create, and paused sandboxes can pick memory and CPU on reconnect.

**TL;DR:** E2B now has a dedicated package for running ACP-compatible agents (goose, OpenCode, Claude Code's ACP adapter) in a sandbox, plus dynamic memory sizing at sandbox creation and reconnect time — two separate releases shipped hours apart on the same day.

**Developer signal:**
1. **e2b-acp v0.1.0:** If you want to run ACP agents in a secure, isolated environment, this is the primitive to use. Create an `ACPAgent` with a sandbox and a command, call `start()`, and your ACP client app connects over stdin/stdout. The sandbox's filesystem and terminal capabilities are disabled from the client side — the agent uses its own tools inside the sandbox. Compatible with goose, OpenCode, and Claude Code via its ACP adapter. Install: `pip install e2b-acp` (Python). Note: `@agentclientprotocol/sdk` 2.x is supported as of v0.1.1 (also released today). This is v0.1 — expect breaking changes in the protocol layer before 1.0.
2. **Resizable memory:** If you create sandboxes with varying workload sizes (e.g., one agent session for a small script, another for a large codebase), you can now set `maxMemoryMB` on templates and override memory per `Sandbox.create()` call. When reconnecting to a paused sandbox via `Sandbox.connect`, pass an object to `onResume` with `action`, `memoryMB`, and `cpuCount` — the sandbox resizes on resume. This replaces the fixed-at-template-creation memory model.
3. **Port-forward CLI:** `e2b sandbox port-forward <sandbox-id> <local-port>:<remote-port>` (alias: `pf`) lets you tunnel a port from a running sandbox to your local machine. Useful for inspecting running services inside a sandbox without opening them to the network.
4. **`sandbox.git` deprecation:** All `sandbox.git.*` methods are deprecated. Migrate to `sandbox.commands.run('git ...')`. The methods still work in 2.65.x/2.66.x but will be removed in a future major version — the migration window is open now.

**Affects you if:** You run agents in E2B sandboxes; you use `sandbox.git` methods (migrate now); you need variable memory for different agent workload sizes; you want to debug running sandboxes via port-forwarding.
**Adoption effort:** Quick (port-forward, getInfo/listBuilds) / Moderate (resizable memory config, ACP integration) / Significant (sandbox.git migration if you have many call sites).
**Primary source:** https://github.com/e2b-dev/E2B/releases (e2b@2.65.0 and @2.66.0, Nov 26 — fetched directly)
*Quality gate score: 9 (official E2B GitHub releases +3; concrete new API names, deprecation call, example use cases +2; primary source GitHub +2; within 24h +1; technical audience +1)*

**What changed:** Beyond the compatibility/breaking changes listed above, v2.75.0 adds `RunContext.submit_output()` for agents to emit intermediate outputs without ending the run, a `Temporal ExternalEventWaiter` for pausing agent runs until an external Temporal event fires, `/trust` in the Pax interface for approving trust escalations interactively, and `pax --version`. Sandbox startup on large repositories is faster via `/sandbox` improvements.

**TL;DR:** Pydantic AI v2.75.0 adds structured intermediate output streaming and Temporal workflow integration, plus performance improvements for large-repo sandboxes.

**Developer signal:** `RunContext.submit_output()` is the key new primitive — it lets a long-running agent emit structured results mid-run, so the calling code can display or act on partial results without waiting for the agent to finish. This is distinct from streaming tokens: it's for semantic checkpoints ("here's the first 10 files I analyzed"). If you use Temporal for durable workflows, `ExternalEventWaiter` lets you suspend an agent run at a checkpoint and resume it when a Temporal event signals completion of an external process — no polling needed. For Pax users, `/trust` and `pax --version` are small but meaningful UX improvements; check that any CI or automation that pins to Pax behavior accounts for the new `/permissions` token-taking handler.

**Affects you if:** You build agents that produce intermediate structured outputs; you use Temporal with pydantic-ai workflows; you use the Pax interface for agent approvals.
**Adoption effort:** Moderate (integrating RunContext.submit_output() into existing agents, Temporal ExternalEventWaiter setup).
