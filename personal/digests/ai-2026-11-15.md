## 🏆 Repo of the Day

### GoogleChrome/modern-web-guidance-src — keeps coding agents off legacy web patterns
**Link:** github.com/GoogleChrome/modern-web-guidance-src | **Stars:** ~7.0k (↑ 1,220 today) | **Language:** TypeScript | **License:** Apache-2.0

**The problem:** Coding agents trained on years of web code produce `jQuery`, custom scroll implementations, and hand-rolled polyfills instead of the native browser APIs that made those patterns obsolete. The result: larger bundles, more maintenance surface, and patterns you have to refactor the moment a human reviewer sees them.

**Why it's today's pick:** 1,220 stars in one day is the strongest single-day gain on today's GitHub Trending list. The project has stewardship from all four major browser vendors (Google Chrome, Microsoft Edge, Mozilla Firefox, and MDN Web Docs), which is unusual — it's effectively the web platform itself telling coding agents what to use. It shipped 250+ verified modern web features and 203 real-world use cases via a CLI that plugs into Claude Code, Gemini CLI, GitHub Copilot CLI, and the Vercel skills CLI. *(Note: star-history.com is DNS-blocked in this session; momentum shown is single-day trending only — recommend validating the star-history curve before making adoption decisions.)*

**Try it in 60 seconds:**
```bash
# interactive install (pick your coding agent integrations)
npx modern-web-guidance@latest install

# or add directly to Claude Code (project scope)
npx plugins add GoogleChrome/modern-web-guidance --scope project --target claude-code

# scan your codebase for patterns the library replaces
npx modern-web-guidance@latest legacy-scan
```

**Instead of:** Manually reviewing agent-generated code for legacy patterns (`element.addEventListener('wheel', ...)` instead of CSS scroll-snap, `XMLHttpRequest` instead of `fetch`, `document.querySelector` loops instead of `querySelectorAll`). The library pulls guidance into the agent's context window so the agent generates modern patterns in the first pass.

**Watch out for:** Launched October 26, 2026 — the project is a few weeks old and content coverage varies by browser feature category. The 37-percentage-point improvement in web best-practice adherence cited in secondary coverage comes from Google's own internal benchmark; no independent third-party eval has been published yet. Treat the benchmark numbers as directional, not established. The `legacy-scan` command is the useful entry point to understand what it would actually change in your codebase before committing to the guidance.

## Trends & Emerging Tech

### The agent protocol stack is converging on three distinct layers: MCP (tools), A2A (agents), AG-UI (users)
**Source:** ag-ui-protocol/ag-ui (github.com/ag-ui-protocol/ag-ui, 17.7k stars, 393 today) | **Date:** ongoing — protocol 1.0 spec freeze reported September 2026 | **Link:** github.com/ag-ui-protocol/ag-ui
**What's happening:** AG-UI (Agent-User Interaction Protocol), an open event-based protocol from CopilotKit, has gained institutional adoption from Google (ADK), Microsoft (Azure Agent Framework, .NET SDK released September 25), and Amazon (Strands Agents). It positions itself explicitly alongside MCP (agent-to-tools) and A2A (agent-to-agent) as the third layer: agent-to-user interaction. The protocol standardizes real-time streaming, bi-directional state sync, generative UI, and human-in-the-loop interrupts over any transport (SSE, WebSockets, webhooks). `npx create-ag-ui-app my-agent-app` bootstraps an integration.
**Why watch this:** As enterprise teams move from single-agent demos to multi-agent production systems, the question of how agents surface state to users — not just what they do internally — becomes a first-class concern. AG-UI filling this gap with cross-vendor backing (the same vendors behind MCP) suggests the three-layer architecture is becoming the de facto standard: build your tools with MCP, wire agents together with A2A, expose the result to users with AG-UI. If your agent UI is currently ad-hoc (custom WebSockets or SSE on top of React), AG-UI is worth evaluating now before it becomes the assumption in every agent framework.

**[PATTERN] The agent protocol stack is converging on three layers — and it's happening faster than expected**

**[TENSION] The agent UI layer is expanding (AG-UI) while agent permissions are contracting (Claude Code v2.1.325)**
AG-UI gives agents more surface to reach users: real-time streaming, generative UI, shared state, human-in-the-loop interrupts through a standardized protocol. Claude Code v2.1.325 (Nov 13 digest) tightened the other direction: sandboxed Bash now requires explicit opt-in, scheduled task skills require pre-authorization. The two trends are simultaneous: agents are getting more UI channels in while having fewer autonomous permissions out. The practical tension for builders: a system designed around AG-UI assumes agents will surface rich interactive state to users, but Claude Code's tightening defaults mean the agent can't act on user responses without explicit pre-authorization. Building an AG-UI-based human-in-the-loop flow on Claude Code today requires carefully mapping every tool use that could follow a user action to its authorization gate.
*Grounded in: ag-ui-protocol/ag-ui integration with Claude Code (this digest, Trends); Claude Code v2.1.325 permission defaults (Nov 14 digest, Breaking Changes)*
