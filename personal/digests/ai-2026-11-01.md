**Link:** github.com/anomalyco/hex | **Stars:** ~3.1k (↑ ~1,300 today) | **Language:** Rust | **License:** MIT
**The problem:** Voice dictation either sends your audio to a cloud server or requires a 900MB+ local model that can't comfortably run alongside a coding agent session.
**Why it's today's pick:** Hex 3.0.0 (Oct 31) is a complete rebuild: the on-device speech model shrank from ~900MB to ~160MB, Windows x64/ARM64 and Linux ARM64 joined macOS as supported platforms, and a vocabulary list was added so you can steer transcription toward technical names your model usually mishears ("pytest", "gRPC", "Bedrock"). DHH included it in Omarchy Dev (his Linux setup) today — the natural endorsement loop for a tool that lives at the intersection of open-source developer setups and coding agents. The 3.0 → 3.1.2 release cadence over 36 hours (four releases on Oct 31-Nov 1) shows active post-launch iteration.
**Try it in 60 seconds:**
```bash
# macOS — download from the GitHub Releases page:
# https://github.com/anomalyco/hex/releases/latest
# (Stable channel; ARM64 and Intel builds available)

# Windows / Linux — same page, Windows x64/ARM64 and Linux x86_64/ARM64 in beta

# After install: configure your hold-to-dictate shortcut,
# click into your Claude Code terminal, hold the key, speak your prompt, release.
# The transcribed text lands exactly where your cursor was.
```
**Instead of:** Typing long natural-language prompts character by character, or using an OS-level dictation feature that doesn't understand technical vocabulary.
**Watch out for:** The star spike (1,300 in a day from a single DHH post) is social-driven — sustained star-history growth isn't yet confirmed. Windows and Linux are explicitly beta: macOS is the primary supported platform. Voice commands and meeting transcription are not included on Linux. The 3.0 rebuild imports nothing from 2.x — full re-grant of permissions and fresh model download required on upgrade.

## Trends & Emerging Tech

### Voice as the primary input surface for coding agent prompts
**Source:** GitHub Trending (anomalyco/hex, #12, Nov 1) | **Date:** 2026-11-01 | **Link:** github.com/anomalyco/hex
**What's happening:** Hex 3.0's Trending appearance, DHH's Omarchy endorsement, and the 5× memory reduction signal that offline voice dictation for coding agents is moving from a niche setup to a plausible default. Three things converged: on-device speech models are now small enough to co-exist with a coding agent session (~160MB vs. the 900MB that was the barrier); Rust-based apps are cross-platform enough to cover Mac/Windows/Linux in a single tool; and the bottleneck in a coding agent workflow is increasingly prompt authoring (human input) rather than agent execution (model output). None of the major coding agents (Claude Code, Codex, Cursor, Cline) have shipped native voice input.
**Why watch this:** If voice input becomes standard, the ergonomic moat of coding agents shifts from context window management (where they've invested most) to input-side UX (where none have yet). The team that integrates native hold-to-talk into a coding agent UI first gets a measurable quality-of-life advantage for teams doing long-session agentic coding. The alternative — keeping voice as an OS/third-party layer like Hex — remains simpler from an engineering standpoint but requires users to compose the setup themselves.

**[PATTERN] The tooling layer around coding agents is growing faster than the agents themselves**

**[OPEN QUESTION] Will coding agent teams add native voice input, or leave it to the OS/third-party layer?**
Hex occupies the gap where no major coding agent has gone: a voice-to-text layer that works with any text input, including agent terminals. The alternatives are native OS dictation (poor technical vocabulary, no hold-to-speak UX) or native agent integration (smoother UX, but engineering investment). None of Claude Code, Codex, Cursor, Cline, or Gemini CLI has shipped native hold-to-dictate. The question is whether this gap gets filled by a third-party tool becoming the de facto standard (Hex's current trajectory) or by one of the major agents building it in and setting user expectations. The first agent to ship native voice input could claim it as a differentiator, but the effort is non-trivial (microphone permissions, cross-platform audio, model size tradeoffs, streaming transcription UX).
*Grounded in: Hex 3.0.0 (anomalyco/hex, Nov 1 Trending, no native voice input in major coding agents)*

**[IF THIS CONTINUES] At the current pace of local speech model compression, offline dictation becomes a one-time 30MB install within two years**
Hex's on-device speech model dropped from ~900MB to ~160MB in a single major version (v2.x to v3.0). Whisper Tiny is already ~39MB; Parakeet CTC 0.6B (a Whisper successor from NVIDIA) is ~600MB but purpose-built for real-time streaming. If the 5× compression-per-generation trend continues, a production-quality offline speech model reaches 30-50MB in 2-3 cycles — trivial to bundle with any developer tool as part of a normal install. At that size, a coding agent could ship its own embedded voice input with zero perceptible install cost. The open question is whether model quality at that size is good enough for technical vocabulary — today's 160MB models still need the vocabulary list to handle "gRPC" reliably.
*Grounded in: Hex 3.0.0 (900MB → 160MB model reduction, vocabulary list for technical terms, anomalyco/hex)*

**[TENSION] Local-first voice dictation vs. the developer's growing cloud compute surface**
Hex's core value proposition is "nothing leaves your machine after the first model download." This is in tension with the broader trend of developer tools moving more work to the cloud: Claude Code cloud sessions, Modal GPU sandboxes, GitHub Codespaces, remote DevPod environments. A developer running their entire coding workflow in a remote cloud session has no natural place to run Hex — voice transcription happens locally, but the agent and the terminal are remote. Bridging this gap requires either piping audio to the cloud session (new attack surface) or the cloud session providing its own microphone access (complex permissions model). Hex works cleanly today only for developers who still run their primary coding setup locally. As cloud-session adoption grows, this becomes a real UX gap.
*Grounded in: Hex 3.0.0 (local-first, anomalyco/hex); Claude Code cloud sessions (Oct 31 digest, cloud session improvements in v2.1.316)*
