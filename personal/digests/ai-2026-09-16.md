## 🏆 Repo of the Day

### max-sixty/worktrunk — git worktrees made fast enough to actually use
**Link:** github.com/max-sixty/worktrunk | **Stars:** ~7.9k (↑ +871 this week) | **Language:** Rust | **License:** MIT OR Apache-2.0
**The problem:** Running multiple AI coding agents in parallel means you need multiple worktrees — but Git's native `git worktree add` commands are tedious, and switching between them is context-destroying friction that breaks the parallel-agent workflow before it starts.
**Why it's today's pick:** The multi-agent pattern is the theme of the week: Claude Code v2.1.273 adds Remote Control session forking, Cline added plugin discovery (yesterday), and worktrunk is the missing link in the local dev workflow — the tool that makes `git worktree` fast enough to be worth doing. Three commands (`wt switch`, `wt list`, `wt merge`) replace a full page of git incantations. It also ships shared build cache support (APFS, btrfs, XFS), LLM-generated commit messages, and integrated merge workflows with diff previews. At 7.9k stars with +871 this week, the growth curve is recent and sustained — not a one-day spike.
**Try it in 60 seconds:**
```bash
# Install (macOS / Linux)
brew install worktrunk
# or: cargo install worktrunk

# Create a new worktree and switch into it (one command)
wt switch --create feature-auth

# List all active worktrees with their status
wt list

# When done: merge, squash, and clean up in one step
wt merge main
```
**Instead of:** `git worktree add ../my-feature origin/main && cd ../my-feature` — repeated for every parallel agent session, with no shared cache and no cleanup path.
**Watch out for:** 7.9k stars is healthy but the tool is still maturing; the LLM-generated commit message feature requires a configured API key. Windows support is via Winget but the developer-experience polish is most complete on macOS/Linux.

## API & SDK Changes

### [MEDIUM] anthropic-sdk-typescript v0.126.0 — Compaction, auto mode, url_sources, tree-shaking
**Source:** GitHub / Anthropic | **Date:** September 15, 2026 | **Link:** https://github.com/anthropics/anthropic-sdk-typescript/releases/tag/sdk-v0.126.0
**What changed:** v0.126.0 (from v0.125.0 on September 10) is the TypeScript counterpart of the Python SDK v1.6.0 released yesterday — bringing compaction support, auto mode tool permissions for Managed Agents, `url_sources` on the web fetch tool, enum types for workspace data-residency geo fields, `workspace_id` on user profile methods, and the `thinking_mismatch_allowed` entries to `input_transformations` (beta). This release also adds `"sideEffects": false` to enable bundler tree-shaking, marks classes as pure for bundler optimization, and fixes TypeScript 5.7 compatibility in declaration files.
**TL;DR:** anthropic-sdk-typescript v0.126.0 reaches feature parity with Python SDK v1.6.0: on-demand compaction, Managed Agent auto tool permissions, web fetch url_sources, and bundler tree-shaking — all in one drop.
**Developer signal:** Four items worth acting on: (1) **Compaction** — `client.messages.create()` now accepts the `compaction` parameter; add `beta: ["compact-2026-09-04"]` to your headers and include the returned compaction block in subsequent requests (see September 15 digest for the full session management pattern). (2) **Managed Agent `auto` permissions** — set `tool_choice: { type: "auto" }` in your Managed Agents config if you want the model to decide which tools to invoke rather than whitelisting them per-call. (3) **`url_sources` on web fetch** — pass a list of authoritative URLs alongside a web fetch call to ground the agent's web search against specific trusted sources. (4) **Tree-shaking** — the `"sideEffects": false` marker means bundlers (webpack, esbuild, Rollup) can now safely drop unused SDK code; if you're building a browser or edge bundle that imports from the SDK, a rebuild after updating to v0.126.0 will likely produce a smaller artifact. Update: `npm install @anthropic-ai/sdk@0.126.0`. No breaking changes from v0.125.0.
**Affects you if:** You use the Anthropic TypeScript SDK for Managed Agents, build multi-turn conversation loops, use the web fetch tool, or bundle the SDK into a browser/edge application.
**Adoption effort:** Quick (npm update, opt in to new features) / Moderate (compaction requires session management loop changes — see September 15 digest).
**Primary source:** https://github.com/anthropics/anthropic-sdk-typescript/releases/tag/sdk-v0.126.0

**Developer signal:** Three things require immediate attention: (1) **Enterprise update required — now:** `managed-settings` (the MDM/fleet-management configuration file) was being ignored rather than enforced, and skills disabled at the org level continued to appear in agent sessions. If your organization uses MDM to configure Claude Code or manages which claude.ai skills are available to users, those policies were not being applied. Update to v2.1.273 immediately with `npm install -g @anthropic-ai/claude-code@latest`. After updating, smoke-test your full config stack — `managed-mcp.json` (fixed in v2.1.271), `managed-settings` (fixed here), and your org's skill disable list. **[OPEN QUESTION] LLM gateway hint headers are opt-in — should they be on by default?**
Claude Code v2.1.273 adds LLM gateway hint headers (`x-claude-code-request-class`, `x-claude-code-agent-type`, etc.) as an opt-in feature enabled by `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`. The metadata these headers carry — request classification by type, agent kind, interactivity level — is exactly what enterprise LLM gateways need for cost attribution and policy enforcement. Making it opt-in makes sense for individual developers (who may not run a gateway), but it's the wrong default for enterprise deployments where a gateway IS the control plane. The open question: why is this opt-in at the user level at all? The right place to enable it is in `managed-settings` (the org-wide config file) so that every Claude Code session behind a corporate gateway automatically sends the headers — the developer doesn't have to set an env var manually. If Anthropic adds gateway-headers as a managed-settings option, the friction for enterprise gateway adoption drops significantly.
*Grounded in: Claude Code v2.1.273 (anthropics/claude-code, Sep 15) — "Added request headers for LLM gateways; opt in with CLAUDE_CODE_GATEWAY_HINT_HEADERS=1"*

**[TENSION] Parallel agent workflows are the next frontier, but the required primitives are fragmenting across incompatible tools**
Three tools this week enable parallel agent workflows: worktrunk (git worktrees for local parallel sessions), herdrdev/herdr (multi-machine session persistence, yesterday's Repo of the Day), and Claude Code Remote Control forking (background forked sessions from the Claude app, v2.1.273). Each solves a real piece of the problem — local branch isolation, session survival across disconnects, and branching from a running session respectively. But they're three different systems with no shared session state, no way to reconcile the outputs, and no common "merge two agent sessions" primitive. The tension: the agent runtime layer is shipping parallelism features faster than it's shipping the coordination layer that makes parallel work actually composable. Until there's a standard for "here are the outputs from three parallel agent branches — pick the best one and merge," the parallelism features will mostly be used for independent tasks rather than true parallel exploration of a single problem.

**[BUILDER'S ANGLE] LLM gateway hint headers + compaction blocks = token-cost attribution across a full agent session**
Two features from the last 48 hours compose into something new. The compaction API (September 14 platform release, September 15 SDK implementations) returns a signed, structured summary of what a conversation contained at each compaction point — you know what the agent "knew" at that checkpoint. Claude Code v2.1.273's gateway hint headers (opt-in) let your LLM gateway see the request class and agent type for every outgoing request. Combine them: instrument your gateway to log token counts per `x-claude-code-request-class` value, and store compaction blocks alongside those logs. You now have: (a) what the agent was thinking at each summary point (compaction block), (b) how many tokens each class of request consumed (gateway logs), and (c) which agent type drove each class of spend. That's a complete per-session cost attribution trace for multi-agent workflows — the kind of observability that enterprise AI teams have been hand-instrumenting. Neither feature was designed for this; it falls out of composing two independently useful primitives.
*Grounded in: Anthropic compaction API (platform.claude.com, Sep 14); Claude Code v2.1.273 gateway hint headers (anthropics/claude-code, Sep 15)*
