## 🏆 Repo of the Day

### evilmartians/lefthook — one binary, any language, sub-second git hooks that actually run in parallel

**Link:** github.com/evilmartians/lefthook | **Stars:** ~10,200 (↑ steady through 2026) | **Language:** Go | **License:** MIT

**The problem:** Git hooks on most teams are either skipped (`--no-verify` by habit) or painfully slow — Husky + lint-staged can add 20–30 seconds to every commit, and that latency kills the habit.

**Why it's today's pick:** A quiet-for-tooling weekend, so reaching into the watchlist here. Lefthook is a single Go binary: no Node.js required (the most common reason teams abandon hook enforcement), runs all hook commands in parallel by default, passes staged files automatically to each command, and stores config in a `lefthook.yml` that gets committed to the repo. With ~10k stars and steady growth, it sits at the threshold between "early adopters" and "mainstream" — now is a good time to add it before it becomes the default assumption in onboarding docs.

**Try it in 60 seconds:**
```bash
# Install (no Node.js required)
brew install lefthook
# Or on Debian/Ubuntu: apt install lefthook
# Or with Go: go install github.com/evilmartians/lefthook@latest

# Init in your repo
lefthook install

# lefthook.yml in repo root:
# pre-commit:
#   parallel: true
#   commands:
#     lint:
#       glob: "*.py"
#       run: ruff check {staged_files}
#     typecheck:
#       run: mypy --fast-module-finder .
```
**Instead of:** Husky + lint-staged (requires Node.js even in Python/Go/Rust projects) or hand-rolled `.git/hooks/` shell scripts that don't get committed and break after every fresh clone.

**Watch out for:** Developers still need to run `lefthook install` after cloning — same requirement as Husky. The v1.10.x release changed some config key semantics; check the migration guide if upgrading from a pre-1.10 install. Windows support is available but less tested than macOS/Linux.

### [MEDIUM] JetBrains Mellum2.1 — 12B MoE open coding model, RL-trained in real software environments, 47% SWE-bench Verified (up from 2%)
**Source:** JetBrains AI Blog (blog.jetbrains.com) / Confirmed via MarkTechPost, DataNorth, BenchLM | **Date:** October 8, 2026 | **Link:** https://blog.jetbrains.com/ai/2026/10/mellum2-1-gets-to-work-a-fast-open-model-for-coding-agents/

**What changed:** Mellum2 (June 2026) → Mellum2.1 (October 8): same 12B MoE architecture (2.5B active parameters, Apache 2.0 license), but post-training replaced with reinforcement learning executed in real software environments (shell + file tools) rather than synthetic examples. ## Trends & Emerging Tech

### Developer API access and platform subscriber access are diverging at the frontier
**Source:** Meta Muse Wonder announcement (Oct 12) | **Date:** October 12, 2026 | **Link:** https://about.fb.com/news/2026/10/introducing-muse-wonder-models/

**What's happening:** Meta launched Muse Wonder Full — its highest-capability model — behind a Muse Code subscription, with no developer API access at launch. This follows a pattern: OpenAI's o1-pro ran subscriber-only for months before API availability; Google Gemini Ultra has always been more restricted than other tiers; Anthropic's Max subscription offers rate limits and capabilities not available on the base API. The frontier API and the consumer-facing best model are no longer the same thing.

**Why watch this:** For developers evaluating models: the best capability in a given lab's lineup may be accessible only as a subscriber, not as a per-token API caller, at least at launch. This creates an asymmetry where internal R&D evaluations (using API access) underrate what competitors' actual products can do (using subscriber tiers). The second-order effect: if the subscriber model turns out to be substantially better for high-stakes tasks, there is pressure to move workloads from API to subscription-based wrappers — potentially trading per-token billing for per-seat pricing and losing fine-grained control over request parameters. The speed of Wonder Full's API availability will be a signal for whether this is a launch tactic or a structural shift.

As model selection for production agent workloads increasingly depends on coding task performance, proliferating incompatible benchmarks turn "which model is best at coding?" into a question that requires its own research project to answer.
