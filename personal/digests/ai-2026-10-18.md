## 🏆 Repo of the Day

### cursor/plugins — Cursor's plugin marketplace spec: standardize skills, rules, and MCP servers for any tool in Cursor
**Link:** github.com/cursor/plugins | **Stars:** ~12,682 (↑ 1,536 this week, +14%) | **Language:** TypeScript | **License:** MIT

**The problem:** Extending Cursor IDE beyond its built-in capabilities requires hand-rolling skills, rules, and MCP server configs with no standard format, no shared discovery, and no way to distribute what you build to other developers.

**Why it's today's pick:** cursor/plugins just merged 5 new plugins in the last 24 hours (Google Ads, Gopuff, Zoho CRM/Desk/Books, QuickBooks Online) and made spec-level changes — a new `/create-formal-verification-skill` skill, skill naming conventions enforced, and a cross-IDE Claude Code adapter. This is not a static spec page; it's an actively growing ecosystem. At 12.7k stars with 14% weekly growth and 70+ plugins (Google, Tailscale, Slack, Playwright, GitHub, Salesforce, and today's additions), the momentum is genuine. This is the Cursor-side counterpart to `anthropics/claude-plugins-official` (42.6k stars) — and the two ecosystems growing in parallel means plugin authors need to understand both.

**Try it in 60 seconds:**
```bash
# As a Cursor user — install a plugin from the marketplace:
# Open Cursor, then open the command palette (Cmd/Ctrl+Shift+P)
# Type: Plugins: Browse Marketplace
# Or install pstack (the flagship plugin) directly via Cursor chat:
# /plugin install pstack

# As a plugin author — clone the spec and scaffold a new plugin:
git clone https://github.com/cursor/plugins
# Each plugin lives in its own folder with:
# .cursor-plugin/plugin.json  ← manifest (name, displayName, description)
# skills/                      ← SKILL.md files
# rules/                       ← .mdc rule files
# mcp.json                     ← MCP server definitions
```
**Instead of:** Manually copying SKILL.md files between projects, hand-writing MCP configs, or shipping undiscoverable AI extensions with no standard install path.

**Watch out for:** The spec is still evolving — skill naming rules changed today (folder name = skill name, lowercase + hyphens, ≤64 chars). If you built plugins against older conventions, the new enforcement may rename or break your skill references. The Releases section is empty; track commits on `main` directly. Cross-IDE support via the Claude Code adapter is new and rough-edged (model choices written to `~/.claude/rules`).

## [BREAKING] Breaking Changes

### [BREAKING] GitHub Copilot — second October model deprecation wave lands tomorrow (October 19): six models removed from all Copilot experiences
**Source:** GitHub Changelog | **Date:** Announced Sep 18, 2026; effective Oct 19 | **Link:** https://github.blog/changelog/2026-09-18-upcoming-deprecation-of-selected-github-copilot-models-in-mid-october

**What changed:** GitHub Copilot is removing six models from the model picker across Chat, inline edits, agent mode, and code completions. Models removed: `GPT-5.5`, `GPT-5.4`, `GPT-5.4 mini`, `GPT-5 mini`, `Gemini 3.7 Flash`, and `Grok 4.5`. Suggested replacements: GPT-5.6 Sol for GPT-5.5; GPT-5.6 Luna for GPT-5.4 mini and GPT-5 mini; Gemini 3.8 Flash for Gemini 3.7 Flash; Grok 4.6 for Grok 4.5. Note: an earlier wave on October 2 already removed Gemini 3.5 Flash, Gemini 3.6 Flash, Kimi K2.7 Code, and Claude Opus 4.7.

**TL;DR:** Six Copilot models removed tomorrow (Oct 19): GPT-5.5, GPT-5.4, GPT-5.4 mini, GPT-5 mini, Gemini 3.7 Flash, Grok 4.5. For Copilot Business/Enterprise, suggested replacements are auto-enabled unless admins have disabled default model enablement.

**Developer signal:** Two things to check before midnight tonight:

1. **Copilot API integrations.** If you call the Copilot API with an explicit model parameter (e.g., `model: "gpt-5.5"` in a GitHub Models or Copilot API call), you'll get an error or a silent fallback after tomorrow. Audit any CI scripts, IDE extensions, or automation that pins these model IDs and update to the replacement model strings. The Copilot API uses the same model identifiers as GitHub Models — verify against the Models marketplace listing for current availability.

2. **Admin-configured model policies.** For Copilot Enterprise/Business, if your organization uses a model allowlist or blocklist policy in Copilot settings, double-check that the replacement models are not accidentally blocked. Default model enablement means replacements should appear automatically, but a policy that explicitly allows only specific models by name will break silently unless you add the new names.

The change applies to Copilot-the-feature (in-IDE chat, inline completions, agent mode). It does not directly affect the models' API availability outside Copilot — but if you rely on GitHub Models as a proxy to access these model versions, confirm their status there separately.

**Affects you if:** You call the Copilot API or GitHub Models API with any of the six model IDs above; you maintain VS Code or JetBrains extensions that depend on pinned Copilot model versions; you administer Copilot for an Enterprise or Business org with model policy settings.

**Adoption effort:** Quick for most (replacement models are auto-enabled); Moderate if you maintain code or policies that explicitly reference the deprecated model IDs.

**Primary source:** https://github.blog/changelog/2026-09-18-upcoming-deprecation-of-selected-github-copilot-models-in-mid-october | October 2 wave: https://github.blog/changelog/2026-10-02-selected-models-in-github-copilot-deprecated

## Trends & Emerging Tech

### AI-native reverse engineering goes mainstream: morluto/rea reaches 320k stars (240k gained this week)
**Source:** GitHub Trending (weekly) | **Date:** October 12–18, 2026 | **Link:** https://github.com/morluto/rea

**What's happening:** morluto/rea — "Reverse Engineer Anything" — gained approximately 240,000 stars in the past 7 days, ending the week at ~320,000. The project is an MIT-licensed MCP server that gives any MCP-compatible agent (Claude Code, Cursor, Codex, Gemini CLI) the ability to inspect and understand native binaries, JavaScript/Electron apps, .NET assemblies, Android APKs, firmware, and packet captures. Analysis runs locally. The install is a single `npx rea-agents setup` — after which any connected agent can call the MCP server to reverse-engineer targets and explain behavior or generate reimplementations.

**Why watch this:** A 240k-star week is extraordinary by any standard — it's one of the largest single-week star gains ever recorded on a non-new repo (the project has 3,719 commits). This signals that the combination of MCP + AI agents + local RE tooling has hit a nerve. For developers, this changes how you can approach "what does this binary/app/APK actually do" questions — instead of manually running Ghidra or jadx, an agent with rea can systematically reconstruct behavior. For security teams, it raises the question: if your customers can do this to your binaries, what does that mean for IP and reverse-engineering-protection assumptions? Worth understanding whether this tool is in your team's threat model.

**[BUILDER'S ANGLE] If rea.tools' MCP server pattern holds, the next unlocked workflow is "agent-native dependency audit"**
morluto/rea shows that an MCP server can give an agent access to RE capabilities that previously required deep manual expertise (Ghidra, jadx, TShark).
