### tobi/disktree — visual treemap for finding and removing what fills your disk

**Link:** github.com/tobi/disktree | **Stars:** ~1,935 (↑ trending today, position 4 on daily Rust) | **Language:** Rust + GPUI | **License:** MIT

**The problem:** `du -sh *` tells you which directories are large but won't show you the individual files inside them or let you mark and delete directly — you still need to navigate into each folder manually to see what's actually taking space.

**Why it's today's pick:** Trending today with ~1,935 stars, built on GPUI (the same GPU-accelerated UI framework powering the Zed editor), and solving a genuinely tedious workflow. "For Omarchy" in the description refers to its origin (a Linux desktop config project), but GPUI means it builds cleanly on macOS and Linux wherever GPUI runs. The visual treemap approach — every directory as a nested mosaic sized by disk cost — lets you see the full picture and mark what goes without leaving the app. In a week when coding agents are generating large artifacts, scratch files, and build outputs, a fast visual disk audit tool is worth keeping in the toolbox.

**Try it in 60 seconds:**
```bash
# Build from source (requires Rust 1.97+):
git clone https://github.com/tobi/disktree && cd disktree
cargo build --release

# Run against your home directory:
./target/release/disktree ~
```
**Instead of:** `du -sh ~/*/` followed by recursive `ls -lhR` dives, or NCDU (terminal-only, no click-to-delete), or WinDirStat (Windows-only).

**Watch out for:** Pre-1.0, no binary releases yet — build from source. GPUI dependency means GPU availability matters; confirmed working on Apple Silicon and NVIDIA Linux. The "for Omarchy" origin means some UX choices are opinionated toward that workflow.

### [MEDIUM] Claude Code v2.1.286 — three credential-exposure security fixes, gateway pricing bug, VSCode bookmarks
**Source:** GitHub Releases | **Date:** September 30, 2026 | **Link:** https://github.com/anthropics/claude-code/releases/tag/v2.1.286

**What changed:** Three log/transcript security fixes (credentials visible in redacted logs via zero-width spaces, percent-encoded Bearer tokens only partly masked, MCP error messages exposing credential values), one gateway billing bug (cache writes at wrong pricing tier), plus credential refresh fixes, parallel-tool-call session resume fix, API 400 fix for non-text tool return values, and VSCode bookmarks.

**TL;DR:** v2.1.286 patches three separate ways Claude Code was leaking credentials into logs and transcripts, fixes a gateway spending meter that underbilled prompt cache writes, and adds VSCode response bookmarks.

**Developer signal:** Three security items to review immediately:
1. **Zero-width-space credential leak in redacted logs/transcripts**: Redacted logs and session transcripts included in feedback zip files were retaining secrets surrounded by invisible characters (U+200B zero-width spaces). If you have exported sessions or submitted feedback that included API keys, tokens, or passwords — and your feedback zip was sent to Anthropic or stored elsewhere — those secrets may have been readable despite appearing redacted. Update to v2.1.286 and audit any transcripts generated before this fix.
2. **Percent-encoded Bearer tokens only partly masked**: Bearer tokens with percent-encoding (e.g., OAuth tokens containing `%2B`, `%2F`) were only partially obscured in logs — the unencoded portion after the last encoded character was visible. Affects anyone using MCP servers with OAuth-style auth tokens.
3. **MCP error messages exposing credential values**: When an MCP server returned an error, the error message could include literal credential values if the token appeared before a key name in the error string (`Bearer <key>`). Fixed: error messages now sanitize these patterns.

Additionally: the Claude apps gateway was pricing 1-hour prompt cache writes at the cheaper 5-minute rate, resulting in underbilling. This is now corrected — gateway spend meters will show higher costs for cache writes going forward. Review your recent gateway billing if cost predictability matters.

New features: VSCode extension gains a **bookmarks** feature to save and revisit Claude's responses within a conversation; Claude Tag (Slack) can now set spend limits directly from a channel ID or Slack link.

**Affects you if:** You use Claude Code with MCP servers that require authentication; you run Claude Code gateway deployments and monitor cost; you have submitted session feedback or exported transcripts that contained sensitive values; you use the VSCode extension.

**Adoption effort:** Quick — Claude Code auto-updates; review prior transcripts if you've submitted feedback with sensitive data present.

**Primary source:** https://github.com/anthropics/claude-code/releases/tag/v2.1.286
*Quality gate score: 8 (official Anthropic source +3; three concrete security fixes with specific mechanisms +2; GitHub releases primary source +2; published today +1)*

The companion fix (folder trust state propagation in headless mode) is equally important: without it, agents running in a subdirectory outside the initially-trusted root would hit trust failures mid-run. Together these two changes make Gemini CLI a viable tool for unattended agent automation. Note: this is a nightly (pre-release) build — use in CI should be pinned to a stable tag once one ships with these changes. The A2A server V1→V2 settings migration is relevant for teams using the experimental agent-to-agent protocol integration.

**Affects you if:** You run Gemini CLI in CI/CD pipelines or as a backend automation tool; you use the A2A (agent-to-agent) server integration; you've been blocked by Gemini CLI requiring interactive confirmation in headless environments.

**Adoption effort:** Quick — pull the nightly; no config changes needed for autonomous mode (it activates automatically in non-interactive sessions).

### Frontier agents fail at multi-software professional engineering tasks — new benchmark reveals the coordination gap
**Source:** arXiv:2609.37686 (EngiWorld) | **Date:** September 29, 2026 | **Link:** https://arxiv.org/abs/2609.37686

**What's happening:** A new benchmark paper — *EngiWorld: What Can Frontier Agents Deliver in Professional Engineering Environments?* — measures how well frontier AI agents perform professional engineering software tasks end-to-end (CAD, simulation, analysis, code, documentation). Key numbers: Claude Opus 5 achieves the highest overall EngiScore at 44.3; GPT-5.6 Sol at 38.0. Both scores are striking for a different reason: on multi-software coordination tasks requiring an agent to operate across two or more engineering applications, only 6 of 168 attempts succeeded across all tested models. That's a 3.6% success rate on coordinated cross-application workflows.

**Why watch this:** The 3.6% cross-application figure is the number to internalize. Professional engineering work is almost always multi-tool (you model in one app, simulate in another, document in a third). The benchmark is telling builders: even Opus 5 fails here 96% of the time — not because the individual application operations are impossible, but because coordinating state across application boundaries breaks down.
