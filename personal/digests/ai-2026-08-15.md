### [NOTABLE] llama.cpp b10441 — `--mmap`/`--no-mmap` Deprecated, Replaced by `--load-mode` Enum
**Source:** llama.cpp / GitHub | **Date:** August 15, 2026 | **Link:** https://github.com/ggml-org/llama.cpp/releases/tag/b10441

**What changed:** llama.cpp b10441 deprecates `--mmap`, `--no-mmap`, and `--mlock` flags in favor of a single `--load-mode` enum with values: `none` (no mmap, equivalent to old `--no-mmap`), `mmap` (memory-mapped, the default), `mlock` (mlock without mmap — note: behavior change from old `--mlock` which implied mmap), and `dio` (direct I/O). The old flags still function with deprecation warnings. Known regression: the previous "no mmap + pin" combination (`--no-mmap` + `--mlock`) no longer has a direct equivalent; this breaks CPU-offload MoE setups using `--n-cpu-moe` (tracked in GH issue #26110).

**TL;DR:** llama.cpp b10441 deprecates `--mmap`/`--no-mmap`/`--mlock` in favor of `--load-mode={none|mmap|mlock|dio}`; the "no mmap + pin" CPU-offload pattern is broken in this redesign (GH #26110).

**Developer signal:** Audit all llama.cpp invocations in scripts, Docker entrypoints, systemd units, and CI: (1) `--no-mmap` → `--load-mode=none`; (2) `--mmap` → `--load-mode=mmap` (or omit — mmap is still the default); (3) `--mlock` → `--load-mode=mlock` (note: new `mlock` means mlock without mmap, different from old `--mlock` which implied both). Old flags are deprecated and log warnings but still work for now — removal will follow in a later build. **If you use `--n-cpu-moe` for CPU-offload MoE models**: the "no mmap + pin" pattern (previously `--no-mmap --mlock`) is broken in this release. Track GH issue #26110 and hold on upgrading to b10441 or later until the fix lands if this pattern is critical for your inference setup.

**Affects you if:** You invoke llama.cpp with explicit `--mmap`, `--no-mmap`, or `--mlock` flags in any scripts or automation; or you use `--n-cpu-moe` with the "no mmap + pin" CPU-offload pattern for MoE models.

**Adoption effort:** Moderate (audit all llama.cpp invocations; replace old flags with `--load-mode`; hold upgrade if you depend on "no mmap + pin" until GH #26110 is resolved).

**Primary source:** https://github.com/ggml-org/llama.cpp/releases/tag/b10441
