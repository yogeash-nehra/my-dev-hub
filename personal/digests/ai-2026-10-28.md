### dandavison/delta — readable, syntax-highlighted git diffs and blame
**Link:** github.com/dandavison/delta | **Stars:** ~29k (steady climb) | **Language:** Rust | **License:** MIT
**The problem:** `git diff` output is hard to scan quickly — no syntax highlighting, no side-by-side layout, and line-level context that misses which logical unit changed.
**Why it's today's pick:** When three separate agentic tooling projects (Claude Code, Gemini CLI, Pydantic AI) ship releases on the same day, you spend time reading diffs. `delta` transforms `git diff`, `git log -p`, and `git blame` into readable, syntax-colored output with optional side-by-side view, word-diff, and language-aware navigation. It integrates into git via a one-line config change — no workflow changes needed. For developers who review AI-generated code changes frequently, better diff UX compounds quickly.
**Try it in 60 seconds:**
```bash
# Install (macOS)
brew install git-delta

# Install (Linux)
cargo install git-delta
# or: latest binary from github.com/dandavison/delta/releases

# Wire up globally — one git config change
git config --global core.pager 'delta'
git config --global interactive.diffFilter 'delta --color-only'

# Now run your normal git diff / log
git diff HEAD~1
git log -p --follow -- path/to/file.py
```
**Instead of:** Piping `git diff` through `colordiff` or relying on IDE diff views that require switching context.
**Watch out for:** delta is a pager, not a full GUI — it works where your pager works. Some terminal emulators have color rendering quirks with wide Unicode characters; v0.16.x added fixes for ambiguous-width rendering that helps. Also: the default theme is opinionated; configure `syntax-theme` in `~/.gitconfig` to match your preferred color scheme.

## [BREAKING] Breaking Changes

### [BREAKING] E2B CLI 2.23.0 — interactive `--select` mode removed from template commands; template is now a required argument
**Source:** GitHub Releases (e2b-dev/E2B) | **Date:** 2026-10-28 | **Link:** https://github.com/e2b-dev/E2B/releases/tag/@e2b/cli@2.23.0
**What changed:** The `-s, --select` interactive mode is removed from `e2b template delete`, `e2b template publish`, and `e2b template unpublish`. In the prior version these commands prompted you to pick a template interactively when none was specified; in v2.23.0 the template ID is a required argument. The unused `-t, --project` and `--team` options are also removed from those commands.
**TL;DR:** Any script or CI job calling `e2b template delete`, `e2b template publish`, or `e2b template unpublish` without an explicit template ID argument will now error rather than prompt.
**Developer signal:** Audit your shell scripts, CI pipelines, and Makefile targets for `e2b template delete`, `e2b template publish`, or `e2b template unpublish` calls that relied on interactive selection (e.g., calls with no template ID or that passed `-s`). Replace them with explicit template IDs. If you were using `-t/--project` or `--team` flags, those are gone — remove them. The positive change in this release is that `e2b template list` now pages correctly for large template sets (up to 1,000 in pretty output, unlimited in JSON via `--json`, configurable with `-l 0` for no limit).
**Affects you if:** You have automation scripts or CI jobs that call `e2b template delete`, `publish`, or `unpublish` and relied on the interactive selector or the `-t/--project` flag.
**Adoption effort:** Moderate (audit and update CLI call sites; straightforward once you know which template IDs to pass).
**Primary source:** https://github.com/e2b-dev/E2B/releases/tag/@e2b/cli@2.23.0

## API & SDK Changes

### [MEDIUM] Pydantic AI v2.63.0 — dynamic_catalog default change, LLMReminder rate change, DetectLoops, IPythonCodeMode, PostgresSpendStore
**Source:** GitHub Releases (pydantic/pydantic-ai) | **Date:** 2026-10-27 | **Link:** https://github.com/pydantic/pydantic-ai/releases/tag/v2.63.0
**What changed:** v2.63.0 ships three behavioral default changes and four capability additions. **Behavioral changes:** (1) `CodeMode` now defaults to `dynamic_catalog=True` — revealed tools are appended rather than rewriting the cached prompt, changing token usage patterns for agents with dynamic tool sets; (2) `LLMReminder` fires every 10 requests by default, down from every request — a 10× reduction in prompt overhead for long-running agents; (3) Gemini Live reconnect replay is now passed to `dial` as a keyword-only `replay` argument; (4) Signed/encrypted history is replayed to providers with a matching `canonical_system`. **New capabilities:** `DetectLoops` capability interrupts agents caught in repeated-action cycles before they run up cost; `IPythonCodeMode` (alongside the Monty-based `CodeMode`) enables Jupyter/IPython kernel execution; `PostgresSpendStore` lets `SpendLimits` budgets be shared across processes or services through a Postgres database; `ag-ui-protocol` 1.0 support; OpenAI `gpt-6.1-terra` model support; `Dataset.evaluate` gains a `task_timeout` parameter.
**TL;DR:** Pydantic AI v2.63.0 makes dynamic tool catalogs the default, cuts LLMReminder prompt overhead by 10×, and ships `DetectLoops` to automatically interrupt agents stuck in action loops.
**Developer signal:** **dynamic_catalog change (highest priority):** If your agents use `CodeMode`, token usage will change after upgrading — appending revealed tools rather than rewriting the cached prompt is cheaper for most use cases but can alter caching behavior if your tool catalog is large. Test token counts on your representative workloads before upgrading production agents. **LLMReminder change:** If you had agents that depended on per-request reminders for correctness (e.g., strict format enforcement on every turn), you'll need to set `LLMReminder(frequency=1)` explicitly to restore the old behavior. **DetectLoops:** Add `DetectLoops()` to any long-running agent that could get stuck — it's a drop-in capability with no configuration required for default loop detection. **PostgresSpendStore:** If you run multiple agent processes that should share a cost budget (e.g., per-user or per-tenant spend limits), `PostgresSpendStore` lets you move that budget out of in-process memory and into a Postgres table — enabling true cross-process spend enforcement.
**Affects you if:** You use Pydantic AI with `CodeMode`; you run long-running agents with `LLMReminder`; you build multi-process agent deployments with shared spend limits; you want automatic loop detection on autonomous agents.
**Adoption effort:** Moderate (behavioral defaults change — test token usage and LLMReminder behavior before upgrading production agents; new capabilities are opt-in).
**Primary source:** https://github.com/pydantic/pydantic-ai/releases/tag/v2.63.0
*Quality gate score: 8 (official GitHub release from Atom feed +3; concrete behavioral changes with specific class names and parameters +2; primary source +2; within window Oct 27 +1)*

## Tooling

### [MEDIUM] Claude Code v2.1.312 — OIDC user_id_claim for gateway, large-file write fix, per-directory skills after `cd`, effort shown in spinner, hook concurrency limits
**Source:** GitHub Releases (anthropics/claude-code) | **Date:** 2026-10-27 (20:24 UTC) | **Link:** https://github.com/anthropics/claude-code/releases/tag/v2.1.312
**What changed:** v2.1.312 follows yesterday's 20+ fix release with a second targeted fix set. **Auth:** Added `oidc.user_id_claim` to the Claude apps gateway so organizations using Microsoft Entra ID (or any IdP that uses a claim other than `sub`) can configure their identifier field. **Large file fix:** Claude no longer overwrites a very large `CLAUDE.md`, rules file, or @-included file after reading only its start — write now prompts Claude to read the full file or edit in place. **Skills routing fix:** Per-directory skills and `paths:`-scoped skills are no longer silently skipped when the working directory changes via `cd` deeper inside a git repo. **Sessions:** Fixed a rare bug where the first reply after resuming a terminal session could be missing on the next resume; fixed sessions incorrectly showing as waiting for user input. **Commands:** Fixed an invalid command name in one plugin/command stopping ALL commands from loading (could leave `claude -p` with no output). **Effort display:** The spinner, OpenTelemetry `effort` values, and transcripts now show the actual effort level in force, not a stale value from earlier in the task. **Telemetry:** `claude_code.safety_event` is no longer sent as an OpenTelemetry event. **Hooks:** Prompt and agent hooks now run at most 24 at a time per session, with at most 12 additional hooks that have exceeded their timeout; a `timeout` under 1 second is treated as 1 second. **Behavior:** Bedrock, Vertex, Foundry, and Mantle use the shorter system prompt for unrecognized model names (set `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0` to keep the full prompt). Usage limit messages now say "5-hour limit" instead of "session limit." **Cloud:** Added an effort picker to cloud routines, and a Bash editor with line numbers to cloud environment setup scripts.
**TL;DR:** Claude Code v2.1.312 fixes per-directory skills silently breaking after `cd`, the large-file overwrite bug, and a command-name crash that could leave `claude -p` silent — plus adds OIDC claim configuration for enterprise gateway.
**Developer signal:** **Skills routing fix (high priority for multi-directory setups):** If you have per-directory CLAUDE.md files or `paths:`-scoped skills and noticed they stopped applying after you `cd`ed deeper into a git repo, this is the fix — upgrade before your next session. **Large-file write fix:** The bug where Claude would overwrite a file after only reading the first chunk was silent and data-destroying — if you have a large `CLAUDE.md` or @-included doc, run `git diff` after this upgrade on any recent changes to verify nothing was corrupted. **OIDC claim configuration:** If you deploy the Claude apps gateway with Microsoft Entra ID or another IdP that uses `oid` or a custom claim as user identifier, set `oidc.user_id_claim` in your gateway config to get proper user attribution rather than falling back to `sub`. **Hook concurrency:** The new 24/12 hook concurrency limits mean hook-heavy setups won't spawn unbounded processes per session — if you have many concurrent hooks and were relying on unlimited parallelism, review the limit.
**Affects you if:** You use per-directory skills or `paths:`-scoped skills; you have large `CLAUDE.md` or @-included files; you deploy the Claude apps gateway with Entra ID; you have many concurrent hooks; you run `claude -p` programmatically.
**Adoption effort:** Quick (drop-in update; check per-directory skills work on next session, verify large files).
**Primary source:** https://github.com/anthropics/claude-code/releases/tag/v2.1.312

**Affects you if:** You run Gemini CLI with OAuth-based MCP servers on private networks; you plan to migrate to Gemini 4 when it ships; you use custom keybindings.

**[IF THIS CONTINUES] If DetectLoops becomes standard across agent frameworks, token billing models need sub-task granularity**

Pydantic AI's `DetectLoops` can interrupt an agent mid-run when it detects repeated actions. If this pattern becomes standard (framework-level auto-interruption), agent cost attribution gets complicated: a task that was billed at completion now terminates early with partial output, and the cost was still incurred. The current billing model (pay per token, no refund for interrupted tasks) works fine when interruptions are rare. At scale, frequent loop detection interruptions could mean a non-trivial fraction of API cost produces zero user value. This is a pre-problem today — `DetectLoops` is opt-in and new — but it's worth thinking about if you build platforms where agent cost is directly tied to user-delivered value.
*Grounded in: Pydantic AI v2.63.0 DetectLoops capability (this digest)*
