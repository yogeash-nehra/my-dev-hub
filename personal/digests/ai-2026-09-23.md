## 🏆 Repo of the Day

### nguyenvuthientrang/cliffcompaction — transparent API proxy that halves coding-agent session costs

**Link:** github.com/nguyenvuthientrang/cliffcompaction | **Stars:** ~19 (brand new — Sep 23 release) | **Language:** Python | **License:** MIT

**The problem:** Long-horizon coding agent sessions balloon context windows into millions of tokens; naive truncation hurts performance; the native compaction in Claude Code and Codex rewrites history which causes cache misses and can lose critical reasoning context.

**Why it's today's pick:** Released today as part of Tim Dettmers' (CMU, known for quantization research) open-source week. Backed by a peer-reviewed paper (arXiv:2609.26779, AACL-IJCNLP 2026) with benchmarked numbers: 50% cost reduction under matched context budget, +10 percentage points on Terminal-Bench 4.0 for less than the cost of two full-context runs. At matched ~45K context, GLM 5.3 Flash scores 76.69% with CliffCompaction vs. 70.97% with Claude Code native compaction — and total session cost drops from $0.548 to $0.268. The key insight: CliffCompaction never rewrites history, it only truncates and drops. This means the kept fragments are verbatim originals, not paraphrased summaries — preserving the reasoning integrity that matters for complex coding tasks. The proxy intercepts both Anthropic Messages API and OpenAI Chat Completions API calls, so it works transparently without any changes to the agent.

**Try it in 60 seconds:**
```bash
uv tool install cliffcompaction
# or
pip install cliffcompaction

cliff enable      # sets environment variables; Claude Code now routes through the proxy automatically
cliff status      # verify the proxy is running
cliff watch       # live view of compaction operations as your session runs
```
For Codex, add a provider block to `~/.codex/config.toml` pointing to the proxy port (see README).

**Instead of:** Claude Code's built-in `/autocompact`, which rewrites and summarizes history (cache-invalidating) and can drop decision-critical context in long sessions.

**Watch out for:** 19 stars as of today — this is day-one software. The paper is reviewed but the proxy implementation is early. Not yet tested on all Claude Code hook and MCP configurations. Keep a fallback path (`cliff disable`) for production pipelines until you've validated on your own codebase patterns.

**Source:** Anthropic (GitHub) | **Date:** September 23, 2026 | **Link:** https://github.com/anthropics/claude-code/releases/tag/v2.1.281

**What changed:** Self-hosted runners now pass system prompts as private files instead of inline CLI arguments. The `--system-prompt` flag is being deprecated; wrappers and CI pipelines must switch to `--system-prompt-file` pointing to a file with the system prompt content.

**TL;DR:** Any wrapper script or CI config that invokes `claude --system-prompt "..."` on a self-hosted runner will need to be updated to use `--system-prompt-file /path/to/system-prompt.txt`.

**Developer signal:** Audit every location in your CI/CD pipelines, wrapper scripts, and runner configuration that passes `--system-prompt` as a direct CLI argument to Claude Code. Create a file with the same system prompt text and update the flag to `--system-prompt-file <path>`. The motivation is privacy: inline flags can appear in process listings and shell history, while a file can be mode-restricted. No changes needed for interactive or SDK-invoked sessions — this only affects self-hosted runner invocations that explicitly pass a system prompt via CLI flag.

**Affects you if:** You operate self-hosted Claude Code runners with `--system-prompt` in your invocation scripts.

**Adoption effort:** Quick — create a file with your system prompt content; replace the flag name; update any scripts that construct the CLI invocation dynamically.

## Research

### [HIGH] A2M: Trace-Optimized Agent Hijacking in the MCP Ecosystem — 93.6% malicious invocation rate via tool metadata poisoning
**Source:** AACL-IJCNLP 2026 (Li L., Wang X., Zhao P. et al.) | **Date:** September 23, 2026 | **Link:** https://arxiv.org/abs/2609.26761

**What changed:** Prior MCP security research focused on prompt injection into tool *outputs*. A2M introduces a two-stage black-box framework targeting the *tool selection* stage: an Attraction phase that optimizes tool *metadata* (name, description, schema) to maximize invocation probability, and a Manipulation phase that uses execution traces to craft adversarial tool returns that steer the agent toward four attack scenarios.

**TL;DR:** On LiveMCPBench across 4 attack scenarios against GLM-4.6, A2M achieves a 93.6% malicious tool invocation rate, 74.4% mean attack success rate, and 32.4× token cost inflation under Cognitive Denial of Service — with no access to model weights or API internals.

**Developer signal:** (1) **Tool metadata is an attack surface.** The A2M Attraction phase works entirely through the text content of a tool's `name`, `description`, and `parameters` fields — no code injection required. If your agent discovers tools from third-party MCP servers (via a registry, marketplace, or user-supplied URL), the metadata in those tool definitions can be crafted to influence which tool your agent calls. (2) **The four attack scenarios are concrete.** Information Exfiltration (tool returns steer agent to leak context), Environment Integrity Compromise (tool returns trigger unintended writes/commands), Reasoning Derailment (tool returns corrupt agent chain-of-thought), and Cognitive Denial of Service (optimized metadata causes 32.4× token overconsumption). All four succeed at rates above 60% in the paper's evaluation. (3) **What to do now:** Treat third-party MCP server metadata with the same distrust you apply to user inputs. For production agents: pin your MCP tool catalog (the `mcp-client-2026-09-15` beta from yesterday's SDK release does exactly this); vet metadata from external MCP servers before allowing agent access; use `claude plugin validate` (added in v2.1.281 today) which now checks for silently dropped entries and insecure URLs; consider filtering tools to an explicit allowlist rather than passing the full server catalog. (4) **Perplexity's Bumblebee** (featured Sep 14) already scans your local MCP servers for known-compromised packages — run it before expanding your MCP server catalog.

**Affects you if:** You build agents that load MCP tools from third-party servers, user-supplied URLs, marketplace listings, or any source you don't fully control. Especially if those tools have write access to the environment.

**Adoption effort:** Moderate — tool catalog pinning requires SDK beta header; allowlist implementation depends on your agent framework; auditing existing MCP metadata descriptions is manual.

**Primary source:** https://arxiv.org/abs/2609.26761 | https://github.com/datnguyenquy94/news-radar/issues/562

### [MEDIUM] CliffCompaction — MIT-licensed transparent proxy cuts long coding-agent session cost 50%
**Source:** arXiv:2609.26779 (Nguyen T., Cho E., Chen B., Dettmers T.) | **Date:** September 23, 2026 | **Link:** https://arxiv.org/abs/2609.26779

**What changed:** Tim Dettmers' lab (CMU) releases CliffCompaction, an open-source autocompaction proxy for coding agents. Unlike summarization-based compaction, CliffCompaction only truncates and drops content — never rewrites — preserving verbatim fragments of decision-critical history while discarding bulky tool output and prior compaction artifacts.

**TL;DR:** At matched ~45K context budget, CliffCompaction reduces total session cost from $0.548 to $0.268 (51% savings) for GLM 5.3 Flash and adds +10 percentage points on Terminal-Bench 4.0 for less than the cost of two standard full-context runs.

**Developer signal:** (1) **The proxy is transparent** — `cliff enable` sets environment variables so Claude Code routes through it automatically. No code changes to your agent or hooks needed. (2) **The key technique is the "compaction cliff" insight:** standard compaction rewrites history into a summary, which creates a cache miss on every compacted session and degrades performance as the summary diverges from the original reasoning. CliffCompaction avoids rewrites by only keeping verbatim fragments (ordered by a learned importance scorer) — the remaining kept context is unchanged, so prompt caching still hits on it. (3) **Both Anthropic Messages API and OpenAI Chat Completions API are supported** — configure once, works with Claude Code (automatic via `cliff enable`) and Codex CLI (manual config block in `~/.codex/config.toml`). (4) **The paper also benchmarks on KernelBench** where the compaction savings make additional test-time scaling compute-efficient. If you run multi-attempt or best-of-N agent loops, CliffCompaction multiplies the effective budget. (5) Caveat: 19 stars, day-one software — treat as experimental for production pipelines. The MIT license and transparent proxy design make it low-risk to try in dev/staging before committing.

**Affects you if:** You run long-horizon Claude Code or Codex sessions that approach context limits; you pay for agent sessions that inflate costs through context overflow; you use test-time scaling or multi-attempt agent loops where cost per run matters.

**Adoption effort:** Quick for Claude Code (`cliff enable`); Moderate for Codex (manual config); evaluate on your own workloads before trusting the paper's numbers as universal.

**Primary source:** https://arxiv.org/abs/2609.26779 | https://github.com/nguyenvuthientrang/cliffcompaction
*Quality gate score: 8 (AACL-IJCNLP 2026 accepted +1; concrete cost numbers: $0.548→$0.268, +10pp Terminal-Bench +2; GitHub repo + PyPI package + arXiv link +2; Sep 23 within window +1; technical audience +1; has runnable code +1; Tim Dettmers recognized researcher: additional trust)*

### Claude's ART enzyme discovery and what it tells developers about multi-agent scale
**Source:** Anthropic | **Date:** September 23, 2026 | **Link:** https://www.anthropic.com/news/claude-discovers-novel-enzyme-system

**What's happening:** Anthropic's new Life Sciences research group used ~950 Claude agents running for 21 hours (210 million tokens) to scan a massive DNA database, gathering 200,000+ reverse transcriptases, narrowing to 3,500 candidate systems, and identifying 20 compelling candidates — ultimately discovering the array-associated reverse transcriptase (ART) system, previously unknown, in bacteriophage DNA. The system has structural similarities to CRISPR (evenly spaced DNA repeat arrays) but is not CRISPR. Wet-lab validation confirmed the array expresses as distinct short RNAs, suggesting functional analogy. Anthropic notes that "researchers are using generated hypotheses themselves as an object of study" to refine instruction quality — the agents aren't just executing a search, they're driving hypothesis generation.

**Why watch this:** The practical signal for developers is the operational model: 950 agents, one prompt, 21 hours, result that took human researchers weeks to months. This is not a demonstration of a new API feature — it's a demonstration of what the current Claude platform can do when operated at scale with careful instruction design. The limiting factors were not the model capability but the instruction quality (Anthropic notes this explicitly) and the hypothesis-validation loop. For developers building multi-agent research or data-mining pipelines: the bottleneck has shifted from "can the agent do this" to "can I write instructions that generate good hypotheses." A secondary signal: 210M tokens at $4/$20 (Opus 5.5 pricing) is roughly $840–$1,680 depending on input/output ratio — a significant but not prohibitive cost for a discovery that would otherwise require weeks of researcher time.
