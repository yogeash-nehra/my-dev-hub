## 🏆 Repo of the Day

### tester-army/e2e — E2E testing that mixes plain-English agent steps with conventional assertions

**Link:** github.com/tester-army/e2e | **Stars:** ~9,000 (↑ 6,564 this week) | **Language:** TypeScript | **License:** check repo

**The problem:** E2E tests break constantly as UI locators drift, and describing complex user flows in raw Playwright selector code buries intent under implementation details.

**Why it's today's pick:** e2e lets you mix natural-language agent steps ("add the first item to cart and proceed to checkout") with conventional locators and assertions in the same test. The framework records which steps the agent performed so subsequent runs replay them without model calls until the app changes — you pay inference cost only when the UI actually changes, not on every CI run. It covers web (Chromium, Firefox, WebKit via Playwright) and mobile (iOS, Android simulators). With 6,564 new stars this week it is the largest single-week gain among developer-productivity repos in the current trending window.

**Try it in 60 seconds:**
```bash
npx e2e init

# Write a test that mixes agent steps with assertions:
# test("checkout flow", async () => {
#   await agent("navigate to products and add the first item to cart");
#   await expect(cartCount).toBe(1);
#   await agent("proceed to checkout and fill in test payment details");
#   await expect(page).toHaveURL(/order-confirmation/);
# });
```
**Instead of:** Writing brittle Playwright locator chains for every UI interaction, or maintaining a separate AI testing layer that can't be co-located with your existing Playwright assertions.

**Watch out for:** No stable release tags — all activity ships on `main`, and the README explicitly notes it is pre-1.0 with APIs that may change. Model key required for agent steps (Anthropic, OpenAI, or a local endpoint). star-history.com was unreachable this scan, so the 6,564-star week is unverified as sustained growth vs. a single-day spike — verify momentum directly on GitHub before committing to it for a production suite.

## API & SDK Changes

### [BREAKING/HIGH] pydantic-ai v2.55.0 — Python 3.10 dropped silently, PostgresStepStore, OpenAIDecisionsModel, unified caching API
**Source:** GitHub / PyPI (pydantic/pydantic-ai) | **Date:** October 9, 2026 | **Link:** https://github.com/pydantic/pydantic-ai/releases/tag/v2.55.0

**What changed:** From v2.54.0 (Oct 2-3): Python 3.10 support dropped (silent version cap), first-class PostgreSQL backends for durable execution state and media storage added, `OpenAIDecisionsModel` backend with image input added, `Conversation` type for multi-run stateful workflows added, unified cross-provider `cache` setting added, and Anthropic cache diagnostics added — the largest feature release in the framework's history.

**TL;DR:** pydantic-ai v2.55.0 requires Python 3.11+, adds a PostgreSQL-backed durable store (`PostgresStepStore`/`PostgresMediaStore`), a unified caching API across Anthropic and OpenAI, `OpenAIDecisionsModel` with image input, and a stateful `Conversation` type for multi-run agents; `openai` floor raised to 3.26.0.

**Developer signal:** Three immediate checks: (1) Python version — `python --version` in every service that uses pydantic-ai. Python 3.10 environments receive v2.54.0 silently on `pip install --upgrade pydantic-ai` with no warning; you stop receiving bug fixes and security patches. Plan the Python 3.11+ upgrade path now. (2) openai dependency floor — `pip show openai` in the relevant venv. The new minimum is 3.26.0; this affects the `openai`, `openrouter`, `bedrock-mantle`, `zai`, `snowflake`, `crusoe`, and `cerebras` extras; a version mismatch causes install conflicts, not import errors. (3) Anthropic caching — add `anthropic_cache_diagnostics=True` to your agent or model config to see per-request cache hit/miss in `provider_details`. If you assumed prompt caching was working but never verified, this surfaces that gap. For teams on Managed Agents building durable multi-step pipelines: `PostgresStepStore` is the first production-grade persistent backend for durable execution in pydantic-ai — no more hand-rolling storage layers. `OpenAIDecisionsModel` runs on GPT-6 Luna via the Decisions API (now in public beta); test it if your pipeline does structured decision trees or typed output extraction with image inputs.

**Affects you if:** You use pydantic-ai with Python 3.10; use any `openai`-dependent extra; use Anthropic with prompt caching and care about observability; or build durable multi-step agents that need persistent state storage.

**Adoption effort:** Moderate (Python 3.11+ migration if on 3.10; openai floor bump; update import patterns for new cache settings); Quick for net-new features

**Primary source:** https://github.com/pydantic/pydantic-ai/releases/tag/v2.55.0

**[BUILDER'S ANGLE] tester-army/e2e's step-recording pattern resolves the hardest problem with AI-driven E2E tests: determinism**
The hardest problem with AI-driven testing is that if the agent re-runs every test from scratch, stability depends on model behavior, which changes with model updates. tester-army/e2e sidesteps this by recording which steps the agent performed and replaying them on subsequent runs until the app changes — the same core insight that made snapshot testing valuable: once you have a passing result, anchor it and only re-evaluate when the subject changes. If this pattern proves reliable at scale, it resolves the "tests are too flaky" objection that has blocked AI-native testing adoption. Watch for similar replay-anchoring patterns appearing in other AI testing frameworks (Playwright AI plugins, Stagehand, etc.) — the idea may generalize quickly.
