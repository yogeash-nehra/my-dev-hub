**The problem:** When a coding agent produces a plan or a large diff, you're reviewing it in a scrolling terminal window with no way to annotate, share, or send structured feedback — every comment is verbal, every rejection means re-typing context.

**Why it's today's pick:** Plannotator has climbed steadily from 3.7k stars (March 2026) to 11k (today) — a consistent, months-long growth curve, not a single-thread spike. It's not a model, a wrapper, or a framework: it's a local browser-based workspace for the review step that every serious agent workflow needs but that no agent ships with. You annotate plans and diffs inline, share reviews with teammates, and send structured feedback to the agent with one click. It has integrations with Claude Code, Codex, OpenCode, and Gemini CLI, and its timing aligns with this week's Claude Code v2.1.325 permission-tightening: as agent workflows move toward human-approval checkpoints, tools like plannotator fill the UI gap that the terminal doesn't.

**Try it in 60 seconds:**
```bash
# install (npm or npx)

# open the workspace for the current repo
npx plannotator@latest open

# or install once globally
npm install -g plannotator
plannotator open
```
Claude Code users: add it as a plugin from the Claude Code marketplace or run `plannotator mcp` to expose its review surface as an MCP server.

**Instead of:** Reviewing agent plans in the terminal and copy-pasting feedback. Plannotator persists the review state, links it to the diff, and creates an audit trail of what you approved and why.

## [BREAKING] Breaking Changes

### [BREAKING] Claude Code v2.1.325 — sandboxed Bash and skill permissions changed by default
**Source:** GitHub (anthropics/claude-code v2.1.325) | **Date:** 2026-11-13 20:40 UTC | **Link:** https://github.com/anthropics/claude-code/releases/tag/v2.1.325
**What changed:** v2.1.323 → v2.1.325: sandboxed Bash no longer runs without prompts by default — it now follows the normal permission flow. Scheduled tasks and `/loop` now ask before running a skill that declares `allowed-tools` or hooks.
**TL;DR:** Claude Code v2.1.325 changes two automation defaults: sandboxed Bash requires a prompt unless `autoAllowBashIfSandboxed: true` is set, and scheduled / looped runs pause before skills with `allowed-tools` or hooks unless pre-approved.
**Developer signal:** Two config changes to audit before the next auto-update:
(1) **Sandboxed Bash:** If you run Claude Code with sandbox enabled and expected Bash to execute without prompts, add `{ "sandbox": { "autoAllowBashIfSandboxed": true } }` to your highest-priority managed settings source (or project/user settings). Without it, any CI or unattended run that uses Bash will now pause and wait.
(2) **Scheduled tasks / `/loop` skills:** If a skill in your loop declares `allowed-tools` or hooks, add it to your allow list: `{ "permissions": { "allow": ["Skill(name)"] } }`. Without this, recurring agent runs that call those skills will stall. The intent is that skills that can run code or call external tools require explicit authorization before running unattended.
Additional behavior changes to review: `--add-dir` (not `additionalDirectories`) is now the correct flag to allow git reads in added directories; `claude remote-control` now exits with status 4 on self-stop and 69 on registration failure (useful for service managers); `CLAUDE_CODE_MAX_CONTEXT_TOKENS` now also sets the context window for unrecognized `claude-*` model IDs (use alongside `CLAUDE_CODE_DISABLE_1M_CONTEXT`); marketplace `ref` now accepts any full commit ID on a branch or tag, but clients before v2.1.325 can't load such pins.
**Affects you if:** You run Claude Code with sandbox enabled in CI or automated workflows; you use scheduled tasks or `/loop` with skills that declare `allowed-tools` or hooks; you use `--add-dir` / `additionalDirectories` in git-related configs; you run `claude remote-control` under a service manager and rely on exit codes.
**Adoption effort:** Quick (add one config key per change) / Moderate (audit all skills used in automated loops)
**Primary source:** https://github.com/anthropics/claude-code/releases/tag/v2.1.325

### [HIGH] Claude Code v2.1.325 — permission hardening + VS Code prompt suggestions + MCP tool description length increase
**Source:** GitHub (anthropics/claude-code v2.1.325) | **Date:** 2026-11-13 20:40 UTC | **Link:** https://github.com/anthropics/claude-code/releases/tag/v2.1.325
**What changed:** v2.1.322 → v2.1.325 (this release covers the gap from v2.1.323, the last release covered in the Nov 13 digest): VS Code gains tab-to-accept prompt suggestions; MCP tool descriptions on the web expand to 16,384 characters (from 4,096); five additional Bash permission edge cases patched; session resume now retains recent turns after unclean exit; Remote Control sessions exit with predictable status codes.
**TL;DR:** Claude Code v2.1.325 ships VS Code prompt suggestions (Tab to accept), raises MCP tool description limits to 16,384 chars for web, fixes five Bash permission edge cases, and addresses session resume gaps — in addition to the two behavior changes in Breaking Changes.
**Developer signal:** **VS Code prompt suggestions:** Tab accepts the suggested prompt in the VS Code terminal panel. If you find this intrusive, disable it with `{ "promptSuggestionEnabled": false }` in your user settings. **MCP tool descriptions:** If you maintain an MCP server used via Claude Code on the web, you can now write up to 16,384-character tool descriptions — a 4× increase that enables richer tool documentation without truncation. **Session resume:** Sessions that ended uncleanly (crash, force-quit) now restore correctly, including recent turns. This fixes a persistent complaint about lost context after a crash. **Bash security:** Five edge cases patched — compound commands, deny/ask rule misses, allow rules running different programs than named, relative rules not applying after `cd`, and sandbox writes to the native updater folder. If you rely on the previous behavior of any of these edge cases (unlikely, but auditable by reviewing your `.claude/settings.json` allow rules), verify the new behavior.
**Affects you if:** You use Claude Code in VS Code and want prompt suggestions; you maintain or use MCP servers with long tool descriptions on the web; you rely on session resume in long agentic workflows; you have custom Bash allow/deny rules.
**Adoption effort:** Quick (auto-update; add config key if disabling prompt suggestions or restoring sandboxed Bash behavior)
**Primary source:** https://github.com/anthropics/claude-code/releases/tag/v2.1.325

## Trends & Emerging Tech

### Claude Code's permission defaults are tightening toward explicit opt-in for automation
**Source:** GitHub (anthropics/claude-code v2.1.325) | **Date:** 2026-11-13 | **Link:** https://github.com/anthropics/claude-code/releases/tag/v2.1.325
**What's happening:** Three Claude Code releases in one week (v2.1.321, v2.1.323, v2.1.325) have each carried Bash permission edge-case fixes and tightened automation defaults. v2.1.325 makes the direction explicit: sandboxed Bash now *requires* opt-in for no-prompt execution (`autoAllowBashIfSandboxed: true`), and skills used in automated loops require pre-authorization. The sandbox is no longer treated as an implicit trust boundary — it's now a containment layer that *adds* a permission step by default, not removes one.
**Why watch this:** Teams running Claude Code in CI or unattended automation are now on a narrowing trust model. The trend suggests Anthropic is responding to real-world reports of agent actions escaping intended scope in production environments. The practical direction: if you're building an automated Claude Code pipeline today, design it around explicit allow lists and the new `autoAllowBashIfSandboxed` flag — rather than assuming sandbox = unrestricted. Future releases are likely to continue this pattern rather than relax it.

### "Agent oversight tooling" is consolidating into its own product category
**Source:** GitHub Trending (Nov 14) | **Date:** 2026-11-14
**What's happening:** backnotprop/plannotator (11k stars, 7-month growth curve) and Tencent/LoopForge (834 stars, launched recently) both independently arrived at the same architectural answer: agents need a structured review and approval layer outside the agent itself. Plannotator solves it at the annotation/diff level; LoopForge solves it at the workflow/SOP level with multi-stage approvals. Both shipped in the same 12-month window and both have cross-agent integrations (Claude Code, Codex, Gemini CLI). This is the first clear signal of a category forming, not just two isolated projects.
**Why watch this:** As enterprise teams scale coding-agent usage, the approval/audit gap is becoming a blocker. Tools that fill it cleanly — with clear UX and integration into existing code review flows — are likely to consolidate fast. Worth watching whether Anthropic or the other major agent platforms absorb this category (as a first-party feature) or leave the third-party layer standing.
