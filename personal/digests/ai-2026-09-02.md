## [BREAKING] Breaking Changes

### [BREAKING] Claude Fable 5.1 — `tool_choice` Types `any` and `tool` Return 400
**Source:** Anthropic Platform Docs | **Date:** September 1, 2026 | **Link:** https://platform.claude.com/docs/en/release-notes/overview
**What changed:** `tool_choice: {"type": "any"}` and `tool_choice: {"type": "tool", "name": "..."}` now return a 400 error when used with `claude-fable-5-1` or `claude-mythos-5-1`. `auto` and `none` are unchanged.
**TL;DR:** Forced tool selection is incompatible with always-on adaptive thinking in Fable 5.1 — use `auto` + strict schemas or structured outputs instead.
**Developer signal:** The root cause matters here: Fable 5.1 has always-on adaptive thinking, which runs before any tool call. Forcing the model to a specific tool (`any`/`tool`) conflicts with the generation order because the thinking block must complete first. Anthropic's documented fix is: (1) set `tool_choice: {"type": "auto"}`; (2) define your tool schemas with `strict: true` to guarantee schema-conformant inputs; (3) if you truly need the model to output a specific structure, switch to structured outputs (`response_format: {"type": "json_schema", ...}`). If you cannot change your calling code immediately, pin to `claude-fable-5` while you migrate — it still supports `any`/`tool`. The migration guide is at `platform.claude.com/docs/en/models/fable-5-1/migration-guide`.
**Affects you if:** You call the Messages API with `tool_choice.type` set to `"any"` or `"tool"` — common in agentic frameworks that force the model into a specific tool step.
**Adoption effort:** Moderate — requires updating tool_choice parameters and potentially switching to strict schemas or structured outputs.
**Primary source:** https://platform.claude.com/docs/en/models/fable-5-1/migration-guide

### [BREAKING] Claude Fable 5.1 — Thinking Blocks Now Model-Bound; New Accounts Get 400 on Replay After History Changes
**Source:** Anthropic Platform Docs | **Date:** September 1, 2026 | **Link:** https://platform.claude.com/docs/en/release-notes/overview
**What changed:** Two new constraints on thinking block reuse: (1) thinking blocks produced by Fable 5.1/Mythos 5.1 are silently dropped when replayed to an earlier model (earlier models can't read them); (2) for accounts created on or after August 31, 2026, replaying thinking blocks after the system prompt, tools, or an earlier message changed returns a 400 error (for older accounts, blocks are dropped silently).
**TL;DR:** Fable 5.1 thinking blocks are forward-only; account-age determines whether history-change replays fail loudly (400) or silently (drop).
**Developer signal:** Three distinct cases to handle: First, if your multi-turn conversation code replays Fable 5.1 conversations to an earlier model (e.g., falling back to Fable 5 for cost), strip thinking blocks before replay — the API now drops them but your code should handle the transformed response shape. Second, if you change the system prompt mid-conversation and replay: on new accounts you'll now get a 400 rather than silent behavior — add explicit error handling for this case. Third, if you use thinking blocks as a form of caching reasoning across turns, note that changing any earlier message invalidates them. The new beta header `thinking-binding-controls-2026-08-01` gives you control over the mismatch behavior: `thinking.block_binding.prefix_mismatch_behavior` accepts `reject` (400) or `drop` (silent), and the `input_transformations` response field tells you what was dropped.
**Affects you if:** You replay multi-turn conversations involving Fable 5.1 thinking blocks to older model versions; you change system prompts or tool definitions across turns while preserving thinking history; your account was created on or after August 31, 2026.
**Adoption effort:** Moderate — requires explicit handling for dropped blocks and 400 errors on history changes.
**Primary source:** https://platform.claude.com/docs/en/release-notes/overview
*Quality gate score: 9 (first-party lab +3, concrete code-level behavior with account-age distinction +2, primary source link +2, within window +1, technical audience +1)*

### [HIGH] Anthropic Enterprise Frontier Safeguards (EFS) — Claude Monitoring Data in Your Cloud, Not Anthropic's
**Source:** Anthropic News | **Date:** September 1, 2026 | **Link:** https://www.anthropic.com/news/enterprise-frontier-safeguards
**What changed:** Anthropic is launching Enterprise Frontier Safeguards (EFS), which shifts storage of Claude's activity monitoring data from Anthropic's infrastructure to the customer's own cloud: AWS S3, Azure Blob Storage, or Google Cloud Storage — under the customer's encryption keys, access policies, and audit logging. Anthropic's misuse detection logic still runs, but when it flags something, the signal goes to the customer's team for review; nobody at Anthropic reads the data.
**TL;DR:** EFS keeps Anthropic's detection running while moving custody of all monitored activity data to customer-controlled cloud storage (S3/Azure Blob/GCS) under the customer's encryption keys — free for eligible enterprise customers, rolling out in phases starting fall 2026. The 30-day retention window remains; only the storage location changes.
**Developer signal:** For enterprise Claude API users: EFS is the unblocking mechanism for Fable 5.1 adoption under existing ZDR agreements. Fable 5.1 requires 30-day data retention, which breaks ZDR; EFS satisfies the retention requirement while keeping the data on your infrastructure. Concretely, until EFS rolls out to your tier (fall 2026), eligible customers get ZDR on Fable 5 and Fable 5.1 in the interim. Implementation requires connecting your cloud storage account during EFS onboarding — Anthropic provides integration guides for AWS S3, Azure Blob, and GCS. Cost model: Anthropic charges nothing for EFS; you pay your cloud provider's storage and egress rates. This was co-designed with 100+ enterprise customers across financial services, healthcare, and public sector — it's demand-driven, not speculative.
**Affects you if:** You're an enterprise Claude API customer under a zero data retention or strict data sovereignty agreement who wants to use Claude Fable 5.1; you operate in regulated industries (financial services, healthcare, government) with audit-log requirements.
**Adoption effort:** Moderate — requires connecting cloud storage during EFS onboarding; no code changes to API calls themselves.
**Primary source:** https://www.anthropic.com/news/enterprise-frontier-safeguards

## Trends & Emerging Tech

### Always-On Thinking Is Reshaping the Claude API Surface
**Source:** Anthropic Platform Docs | **Date:** September 1, 2026 | **Link:** https://platform.claude.com/docs/en/models/fable-5-1/overview
**What's happening:** Fable 5.1's always-on adaptive thinking is the root cause of the tool_choice breaking change — you can't force tool selection before a thinking block completes. This is the second consecutive model generation (after Fable 5's extended thinking option) where thinking has become more of a first-class primitive rather than an opt-in mode. The pattern suggests Anthropic is treating thinking as an inescapable part of its frontier model architecture going forward.
**Why watch this:** If future Claude models all have always-on thinking, the `tool_choice: any/tool` pattern — used extensively in agentic frameworks to guarantee structured outputs — becomes permanently unsupported. The Anthropic-recommended replacement (structured outputs + `auto` tool choice) is more declarative and arguably more robust, but requires rewriting a large surface area of LangChain, LlamaIndex, and custom agent code that relies on forced tool selection. Monitor whether major agentic frameworks update their Claude adapters in the next few weeks; if they do, this migration will be invisible to most developers. If they don't, it becomes a hard blocker for Fable 5.1 adoption.

### 0.025x Cache Pricing: Fable 5.1 Is 4× Cheaper for Cache-Heavy Workloads
**Source:** Anthropic Platform Docs | **Date:** September 1, 2026 | **Link:** https://platform.claude.com/docs/en/release-notes/overview
**What's happening:** Claude Fable 5.1 prompt cache reads cost $0.25 per MTok (0.025x base input price of $10/MTok). Every other Claude model charges $1/MTok for cache reads (0.1x base). At a 500k-token cached system prompt read across 10,000 daily calls, Fable 5.1 costs $1,250/day in cache reads; the same workflow on Fable 5 costs $5,000/day. This is not a promotional rate — it's listed as the standard pricing.
**Why watch this:** This pricing structure may indicate that Anthropic expects Fable 5.1 to be used in heavily cached, long-context, repeated-call patterns (agentic research, document processing, long-running coding assistants). It also sets a competitive pressure on inference providers: if you can get 4× cheaper cache reads from Anthropic direct, the economics of going through a third-party provider (Bedrock, Fireworks, etc.) with a markup become harder to justify at scale. Watch whether OpenAI or other labs respond with competing cache pricing changes.

**[OPEN QUESTION] At What Cache-Reuse Rate Does Fable 5.1 Beat Smaller Models on Cost?**
Fable 5.1 cache reads: $0.25/MTok (0.025x). A hypothetical smaller model (e.g., Haiku 4.5 at $0.80/$4 per MTok) has cache reads at roughly $0.08/MTok (0.1x). **[BUILDER'S ANGLE] Per-Message Effort + Turn-Scoped System Messages = Dynamic Reasoning Budget Per Agent Step**
Fable 5.1 launches with two new beta features: per-message effort control (change thinking budget per turn without rebuilding the conversation) and turn-scoped system messages (inject per-turn instructions that don't accumulate in context or invalidate cache). Combined, these enable a new pattern: an orchestration layer can inject `effort: "high"` + a detailed planning prompt for the hard step (code generation, reasoning), then drop back to `effort: "low"` for lightweight steps (status checks, formatting) — all without cache invalidation. This is the developer API for dynamic reasoning budgets in multi-step agents. No one is using it yet because it just launched in beta, but it's the building block for cost-optimized agentic pipelines that don't pay "always thinking hard" costs on every single turn.
*Grounded in: Fable 5.1 per-message effort beta + turn-scoped system messages beta (this digest)*
