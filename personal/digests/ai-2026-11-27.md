## [BREAKING] Breaking Changes

### [BREAKING] MCP Servers v2.6.0 — 8 security vulnerabilities patched across mcp-server-git, server-memory, mcp-server-fetch, server-filesystem
**Source:** modelcontextprotocol/servers | **Date:** 2026-11-27 | **Link:** https://github.com/modelcontextprotocol/servers/releases/tag/v2.6.0

**What changed:** A single security release patches 8 vulnerabilities. `mcp-server-git` gets 7 fixes (up from 2026.11.18): Git LFS no longer runs programs named in repo config, `--repository` roots that point to another repo via `.git` file are refused, `git_remote` redacts credentials in crafted remote names/URLs, `repo_path` no longer expands environment variables, `git_show` now reads only the repository's own objects, `git_merge` refuses merges that would overwrite ignored files (e.g., `.env`), and the `--repository` check re-runs after any tool writes to the working tree. `server-memory` 2.2.2 fixes a symlink attack that let a save change permissions on files outside the memory path. `mcp-server-fetch` fixes a robots.txt bypass via backslash and path-parameter spellings. `server-filesystem` 2.4.1 (Windows only) refuses paths with junctions or symlinks that change during a directory read.

**TL;DR:** MCP Servers v2.6.0 patches 8 CVEs across 4 servers; `mcp-server-git` had the most critical fixes — credential leaks and repo root traversal — affecting all versions through 2026.11.18.

**Developer signal:**
1. **Upgrade mcp-server-git to 2026.11.27 immediately.** GHSA-wvv2-676g-r57j (credential leak via `git_remote`) and GHSA-f33v-89w7-f9vc (env var expansion in `repo_path`) are exploitable by any input that reaches those tools — if your agent passes user-supplied strings to git operations, this is a live risk. Update now.
2. **Repo root traversal (GHSA-3whj-m8jj-x97q):** If you use `--repository` and your working directory contains a `.git` *file* (not a folder) pointing to another repo — a common pattern in git worktrees and submodules — the server previously accepted that as a valid root. It now refuses. If your automation uses git worktrees, test the `--repository` path before deploying the update.
3. **`server-memory` on files with symlinks:** GHSA-48j5-hj63-c82c. If your memory graph root contains or is adjacent to symlinks, the previous behavior could change file modes on the symlink target. Upgrade to 2.2.2 now.
4. **npm package managers won't auto-upgrade** `server-memory` from date-versioned installs. Run `npm install @modelcontextprotocol/server-memory@2.2.2` and `npm install @modelcontextprotocol/server-filesystem@2.4.1` explicitly.
5. **New behavior changes (not just security):** `git_merge` will now refuse merges that would overwrite ignored files. If your agent workflow does automated merges, test that ignored-file handling still works as expected.

**Affects you if:** You run `mcp-server-git` with any user-controlled or agent-controlled input (remote URLs, repo paths, branch names); you use `server-memory` with a graph root near symlinks; you use `mcp-server-fetch` with robots.txt enforcement; you use `server-filesystem` on Windows.
**Adoption effort:** Quick (version bump) for most. Moderate if you need to test git worktree/`--repository` behavior after the traversal fix.
**Primary source:** https://github.com/modelcontextprotocol/servers/releases/tag/v2.6.0

### [BREAKING] Pydantic AI v2.76.0 — `read_file` offset now 1-indexed; Gemini 2.5 deprecation warnings; `UpdateTools` for realtime sessions
**Source:** Pydantic AI | **Date:** 2026-11-26 (23:49 UTC) | **Link:** https://github.com/pydantic/pydantic-ai/releases/tag/v2.76.0

**What changed:** Three breaking changes: (1) `FileSystemToolset.read_file` `offset` is now 1-indexed — code passing `offset=N` must pass `N+1`, and `offset=0` now raises. (2) `RealtimeInput` gains a new `UpdateTools` variant — exhaustive `assert_never` matches over `RealtimeInput` stop type-checking until they handle `UpdateTools`. (3) `gemini-2.5-pro` and `gemini-2.5-flash` via `GoogleModel`/`GoogleInteractionsModel` now emit `DeprecatedModelWarning` — setups that treat `UserWarning` as errors will fail.

**TL;DR:** Pydantic AI v2.76.0 has three breaking changes: `read_file` offset is 1-indexed (old code silently reads from the wrong position), `UpdateTools` is added to `RealtimeInput` exhaustive patterns, and Gemini 2.5 models now emit warnings before deprecation.

**Developer signal:**
1. **`read_file` offset change is the most likely silent breakage.** If you use `FileSystemToolset.read_file` with any `offset` argument, every call that passes `offset=N` now reads from line `N+1` of the file. No error is raised for non-zero offsets — the read just starts one line late. Grep your codebase for `read_file.*offset` and add 1 to every value. `offset=0` now raises, so catch that case too.
2. **`UpdateTools` in realtime sessions:** This is a new feature (see Tooling section), but if you have `assert_never` in an exhaustive match over `RealtimeInput`, you need to add a case for `UpdateTools` before upgrading. Check any type-narrowing code that exhausts `RealtimeInput` variants.
3. **Gemini 2.5 deprecation warnings:** If you use `GoogleModel` or `GoogleInteractionsModel` with `gemini-2.5-pro` or `gemini-2.5-flash` and have `warnings.filterwarnings('error')` or `pytest -W error`, your code will fail on the next invocation. Add `warnings.filterwarnings('ignore', category=DeprecatedModelWarning, module='pydantic_ai')` or switch to a non-deprecated model now.
4. **Pax `Selection` API changed (#14558):** `Selection.feed` now takes `now`; `Selection.span` takes `frame` and `joins` in place of `width`; `highlight` and `text` take `joins`. If you use the Pax selection API in custom plugins, update call sites.

**Affects you if:** You use `FileSystemToolset.read_file` with any `offset` argument; you have exhaustive `RealtimeInput` matches; you use Gemini 2.5 models via `GoogleModel`/`GoogleInteractionsModel` with warnings-as-errors; you use the Pax `Selection` API.
**Adoption effort:** Moderate (audit `read_file` call sites, update `RealtimeInput` matches, verify Gemini warning handling).
**Primary source:** https://github.com/pydantic/pydantic-ai/releases/tag/v2.76.0
*Quality gate score: 9 (official pydantic-ai release +3; specific breaking API changes with named parameters and code examples +2; primary source GitHub releases +2; within 24h of Nov 27 +1; technical audience +1)*

**[OPEN QUESTION] Will the `read_file` 1-indexed offset change in Pydantic AI produce a wave of silent bugs before developers notice?**
