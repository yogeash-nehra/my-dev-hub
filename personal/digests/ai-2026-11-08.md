## 🏆 Repo of the Day

### max-sixty/worktrunk — git worktree management CLI built for parallel AI agent workflows
**Link:** github.com/max-sixty/worktrunk | **Stars:** ~12,094 (↑ 2,292 this week) | **Language:** Rust | **License:** MIT / Apache-2.0
**The problem:** Native `git worktree` commands are verbose and low-level — switching to a worktree requires remembering the path, `add` requires repeating the branch name, and there's no way to share build caches across worktrees without manual setup.
**Why it's today's pick:** The move to parallel AI coding agent workflows (running Claude Code on feature branches concurrently, using `isolation: "worktree"` in Claude Code to give each agent its own checkout) has turned git worktree management from an occasional power-user task into a daily workflow primitive. worktrunk has been climbing steadily on GitHub Trending weekly all month (+2,292 this week), which tracks exactly with the spread of parallel agent patterns. v0.81.0 (Oct 20) added interactive foreground hooks that inherit stdin — which matters when your pre-commit hooks need to prompt for input during an agent-run commit — and `wt merge --branch` for merging another worktree's branch without leaving your current one. It calls itself "the most popular git worktree manager," and the star history supports that claim.
**Try it in 60 seconds:**
```bash
# Install via Homebrew
brew install max-sixty/worktrunk/worktrunk

# Or via Cargo
cargo install worktrunk

# List your current worktrees with CI status
wt list

# Switch to or create a worktree for a branch (creates if it doesn't exist)
wt switch feature/my-branch

# Check out an open PR as a worktree
wt switch pr:123

# Merge another worktree's branch from where you are
wt merge --branch feature/other-branch

# Remove a worktree and clean up
wt remove feature/my-branch
```
**Instead of:** `git worktree add ../my-branch my-branch && cd ../my-branch` (or `git worktree list` / `git worktree remove` for every operation) — worktrunk replaces all of this with branch-name-based addressing.
**Watch out for:** v0.81.0 has breaking changes — hooks no longer receive context as JSON on stdin (now passed as template arguments), and the template engine moved to MiniJinja 3 (affecting `round` and `title` behavior). The Releases section on GitHub is populated with detailed changelogs, so check v0.81.0 notes before upgrading from earlier versions. Nushell 0.113+ required if you use Nushell integration.

**[IF THIS CONTINUES] The parallel-agent workflow pattern will make single-threaded dev environments feel like a bottleneck**
Today's concurrent coding agent setups (3–5 agents on separate worktrees) are constrained by: (1) build cache sharing — worktrunk's copy-on-write feature helps on APFS/btrfs/XFS; (2) worktree lifecycle management — worktrunk solves this; (3) CI slot availability — most CI systems still run jobs serially. If parallelism of 10–20 concurrent agents becomes normal (the star growth on tools enabling this suggests adoption is tracking upward), the bottleneck moves from "how do I run multiple agents" to "how do I merge their outputs without conflicts." The merge problem at high parallelism is not solved by any currently trending tool — it's the next unsolved primitive after worktree management.
