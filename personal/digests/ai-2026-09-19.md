## 🏆 Repo of the Day

### bendlang/bend — LAWS.bend: a file that makes AI-generated code violations fail at compile time

**Link:** github.com/bendlang/bend | **Stars:** ~21.7k (↑ +21.7k in 3 days since Sep 17 launch) | **Language:** Haskell (compiler), Python-like user syntax | **License:** Apache-2.0

**The problem:** AI coding agents write code that compiles and passes tests — but silently breaks a business invariant. No type system catches "balance conservation is violated"; no test suite reliably prevents it at scale.

**Why it's today's pick:** Bend 2 launched September 17 with a direct answer to the AI-code-correctness problem. Write your invariants in a `LAWS.bend` file — "no game state leads to victory," "total token supply is conserved," "no negative account balance" — and the Bend compiler re-proves them after every code change, including AI-written ones. A patch that breaks a declared law produces a proof failure, not a runtime bug. Creator Victor Taelin (author of the HVM interaction-combinator runtime) spent 10 years on dependent-type theory; the proof checker handles under a second what other tools take minutes on. The HN thread opened September 19 with 589 points and 302 comments — the highest-scoring developer-tool post of the day. Compiles to C, Metal, CUDA, and JavaScript.

**Try it in 60 seconds:**
```bash
# Install
curl -fsSL https://bend-lang.com/install.sh | sh

# Declare an invariant
cat > LAWS.bend << 'EOF'
law no_negative_balance (acc : Account) :
  acc.balance >= 0
EOF

# Attempt to build code that violates it — compiler refuses with a proof failure
bend build
```

**Instead of:** Writing regression tests for every invariant and hoping AI doesn't write code that passes the test while violating the spirit.

**Watch out for:** Launched September 17 — very early. CUDA and Metal backends are experimental. Dependent-type error messages can be cryptic until the model clicks. Existing codebases need to be ported to Bend syntax. Read the HN thread (589 pts, 302 comments) before committing to the system — several threads discuss where dependent types can't express what you want.

### [BREAKING] E2B @e2b/desktop-python@2.6.0 — `allow_internet_access` no longer defaults to True; `secure` parameter deprecated
**Source:** E2B (GitHub) | **Date:** September 18, 2026 | **Link:** https://github.com/e2b-dev/E2B/releases

**What changed:** In @e2b/desktop-python@2.6.0, `allow_internet_access` previously defaulted to `True` for desktop sandboxes. It now passes no default, meaning the API's own default applies — which is no internet access. Any desktop sandbox created without explicitly passing `allow_internet_access=True` will now be isolated from the internet on update. The `secure` option is also deprecated (still accepted but ignored) — all sandboxes use v2 API with secured envd access by default.

**TL;DR:** @e2b/desktop-python@2.6.0 removes the `allow_internet_access: True` default — desktop sandboxes now create without internet access unless you explicitly opt in; `secure` parameter is deprecated (ignored).

**Developer signal:** (1) **Audit all desktop sandbox creation calls** before updating to @e2b/desktop-python@2.6.0. If you relied on `allow_internet_access` defaulting to True (for browser automation, API calls, or anything requiring outbound internet from the desktop sandbox), add `allow_internet_access=True` explicitly in Python or `allow_internet_access: true` in TypeScript. (2) **Remove `secure` parameter calls** — the parameter is deprecated and silently ignored. All sandboxes now use secured envd access via the v2 API endpoint. (3) **Also check main SDK usage (e2b@2.51.0)** — the 5-minute sandbox timeout default is gone from the client; pass an explicit `timeout` parameter if your code relied on the client-side safety cap. (4) **Client-side fork count validation removed** — the API now validates fork `count` directly. Edge-case fork operations at the old client-side validation boundary may now surface as API errors rather than client-side rejections.

**Affects you if:** You create E2B desktop sandboxes that need internet access; you rely on the default 5-minute sandbox timeout in the main SDK; you call the deprecated `secure` parameter on sandbox creation.

**Adoption effort:** Moderate — add `allow_internet_access=True` explicitly to desktop sandbox creation where needed; add explicit `timeout` to main SDK sandbox creation if you relied on the default; remove `secure` parameter.

(4) **Trajectory-level insight**: Planning changes where runs stop; action space changes code granularity; context management changes run length. These are separable levers — you can tune each independently.
