## [BREAKING] Breaking Changes

### [BREAKING] Claude Code v2.1.326 — sandboxed writes to sensitive home folders blocked by default; hook blocking behavior expanded
**Source:** Claude Code Docs Changelog | **Date:** 2026-11-16 | **Link:** https://code.claude.com/docs/en/changelog
**What changed:** Two behavior changes in v2.1.326 require active attention. (1) **Sandbox home-folder writes**: sandboxed commands on macOS, Linux, and WSL can no longer write to some sensitive home-directory paths by default. Use `sandbox.filesystem.allowWrite` in your settings to restore specific paths. (2) **Hook block expansion**: a hook returning `"decision": "block"` now holds in more edge cases than before — hooks that always returned a `block` decision may start blocking tool calls that previously slipped through. Additional changes: Claude's file tools now refuse writes to sign-in files such as `.credentials.json`; some PowerShell commands now require approval or are denied outright; `/plugin` uninstall/remove/switch prompts changed from `y`/`n`/`u` keys to arrow-key navigation + Enter; `claude mcp serve` ignores `sandbox.excludedCommands`; `--await-initialize` is refused with `--bg` or `--worktree --tmux`.
**TL;DR:** Claude Code v2.1.326 ships 59 improvements and 233 bug fixes, with two default-behavior changes that can silently break sandbox-dependent workflows: sensitive home-folder writes are now blocked unless explicitly allowed, and hook blocking now catches more cases.
**Developer signal:** (1) After upgrading, test whether any agent-generated commands that write to `~/.ssh`, `~/.aws`, `~/.kube`, or similar dirs are now blocked — add `sandbox.filesystem.allowWrite: ["~/.aws/cache"]` (example) for paths you intentionally allow. (2) Review every hook that returns `"decision": "block"`: if it's a catch-all that returns block on every call, it may now block tool calls it didn't before — add an explicit condition. (3) Update any CI or automation scripts that use keyboard shortcuts for `/plugin` operations (`y`/`n`/`u` are no longer valid). Code Mode can now be turned on while agent teams are enabled — these two features now work together. Remote Control now connects through a CONNECT tunnel: if you use a proxy, it must allow CONNECT or Remote Control will fail with an error.
**Affects you if:** You run Claude Code with sandboxed Bash on macOS/Linux/WSL and write to home-directory paths; you use hooks that return `"decision": "block"`; you automate `/plugin` commands; you run Remote Control behind a proxy that blocks CONNECT tunnels.
**Adoption effort:** Moderate (audit sandbox allowlists and hooks before upgrade; CI scripts using /plugin need updating).
**Primary source:** https://code.claude.com/docs/en/changelog

### [BREAKING] Hugging Face Inference Providers now route all language models through OpenRouter — custom provider API keys removed
**Source:** Hugging Face Blog | **Date:** 2026-11-16 | **Link:** https://huggingface.co/blog/openrouter
**What changed:** Hugging Face replaced its own routing layer behind Inference Providers with OpenRouter's router for language models. As of Nov 16, custom provider API keys (e.g., your own Together AI or Fireworks key passed to the HF Inference API) **no longer work for language models**. All language-model inference through the HF API now bills to your Hugging Face account. OpenRouter dynamically selects the best provider for each call based on price, speed, and reliability, retrying elsewhere on failure. Image, video, and audio generation still use direct Inference Providers and retain custom key support.
**TL;DR:** HuggingFace has handed language-model routing to OpenRouter, breaking the custom-provider-key pattern — 160 chat models from 38 labs are now routed via OpenRouter, with billing through HuggingFace at provider price (no HF markup).
**Developer signal:** Audit every integration that passes a provider-specific API key to the HuggingFace Inference API for a language model. The `provider` + `api_key` parameter pattern no longer works for chat models — remove those keys; requests will route automatically and bill your HF account. To influence routing, use the model-id suffix syntax (`model-id:provider-name`) or disable specific providers in your HF settings. The HF token and API endpoint are unchanged. If you use HF inference for image/video/audio generation, nothing changes for now — those stay on direct Inference Providers. Per HF's data: open-weight models grew from 26.8% of inference tokens on HF in Oct 2025 to 71.7% by Sep 2026 — this routing change is built for that scale.
**Affects you if:** You pass custom provider API keys (Together AI, Fireworks, Deepinfra, etc.) to the Hugging Face Inference API for language models; you build apps on the HF Inference API and want predictable provider routing; you care about which provider processes your requests.
**Adoption effort:** Moderate (audit all integrations using custom provider keys; update provider selection to model-id suffix format).
**Primary source:** https://huggingface.co/blog/openrouter
*Quality gate score: 9 (official Hugging Face blog +3; concrete breaking change — custom API key removal — with migration path +2; primary source +2; within 24h window +1; technical audience +1)*

**[PATTERN] Routing layers are centralizing even as models decentralize**
HuggingFace's move to hand language-model routing to OpenRouter (this digest, Nov 16) is structurally interesting: the models themselves are more open than ever (71.7% of HF inference is open-weight, up from 26.8% a year ago), but the control plane for *which provider runs them* is now concentrated at OpenRouter. This mirrors what happened in cloud infrastructure: compute became commodity (many providers), but traffic routing centralized around a few load-balancers and CDNs. For developers: open model access is cheaper and more reliable than ever, but provider-specific behavior (latency guarantees, geographic routing, model variants) is now harder to control directly through HF. The model-id suffix (`model-id:provider`) is the escape hatch, but it requires knowing which provider to prefer — which is now OpenRouter's job.
*Grounded in: Hugging Face blog (openrouter, Nov 16); open-weight inference token share 26.8% → 71.7% (Oct 2025 → Sep 2026)*
