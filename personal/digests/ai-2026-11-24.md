## [BREAKING] Breaking Changes

### [BREAKING] Claude Code v2.1.331 — Windows HKLM managed settings now outrank managed-settings.json
**Source:** Claude Code Changelog | **Date:** 2026-11-23 | **Link:** https://code.claude.com/docs/en/changelog
**What changed:** On Windows, `HKLM` managed-settings registry policies are now checked at startup and outrank `managed-settings.json`. A broken or unrecognized HKLM value can prevent Claude Code from starting.
**TL;DR:** If you deploy Claude Code on Windows in an enterprise environment with both HKLM registry policies and `managed-settings.json`, the registry now wins — verify HKLM entries are valid before upgrading, or Claude Code may fail to start.
**Developer signal:** Run `regedit` and check `HKEY_LOCAL_MACHINE\SOFTWARE\Anthropic\ClaudeCode` (or equivalent path) for any stale, mistyped, or test values before upgrading to v2.1.331. If Claude Code fails to start after the upgrade, an invalid HKLM value is the first place to look. If you use only `managed-settings.json` and have no HKLM policy, this change does not affect you.
**Affects you if:** You deploy Claude Code on Windows with HKLM group policy or registry-based managed settings.
**Adoption effort:** Quick (review HKLM registry entries before upgrading).
**Primary source:** https://code.claude.com/docs/en/changelog (v2.1.331, Nov 23 entry — fetched directly)

### [MEDIUM] Claude Code v2.1.331 — Code Mode on all 4 enterprise cloud providers, OTEL span improvements, 95 fixes
**Source:** Claude Code Changelog | **Date:** 2026-11-23 | **Link:** https://code.claude.com/docs/en/changelog
**What changed:** Code Mode — Claude's JavaScript-native tool-call execution mode — expanded from Claude-API-only to terminal sessions on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry, and Claude Platform on AWS. OTEL span attributes on `claude_code.llm_request` gained `gen_ai.usage.*`, `gen_ai.response.model`, and `gen_ai.operation.name`; `gen_ai.usage.input_tokens` now includes prompt cache tokens. 95 bug fixes.
**TL;DR:** Code Mode now runs on Bedrock, GCP Agent Platform, Foundry, and AWS Claude Platform in terminal sessions; OTEL LLM request spans gained standard gen_ai.* attributes plus prompt cache token counts; 95 fixes cover MCP tool-call hangs, Stop hooks, and /compact summary loss.
**Developer signal:** (1) **Code Mode on enterprise platforms** — if you run Claude Code terminal sessions on Bedrock, GCP, Foundry, or AWS Claude Platform, Code Mode is now available. Enable it in `/config` or by passing `--code-mode` at startup. No gateway or provider configuration change required. (2) **OTEL span updates** — if you have an OTEL exporter configured via `CLAUDE_CODE_OTEL_ENDPOINT`, your LLM request spans now carry `gen_ai.usage.input_tokens` (which includes prompt-cached tokens), `gen_ai.usage.output_tokens`, `gen_ai.response.model`, and `gen_ai.operation.name`. Update any dashboards or alert rules that parse span attributes — if you were using custom attribute names for cost attribution, the standard gen_ai.* names are now available as the canonical source. Crucially, `gen_ai.usage.input_tokens` including prompt cache tokens enables cache-aware cost attribution at the trace level for the first time. (3) **Plugin `optionalDependencies`** — plugin authors can now declare optional dependencies in their manifests; they install with the plugin but can be disabled or uninstalled independently. Useful for plugins with large optional features (charting, language-specific tooling). (4) **VS Code additions** — "Fix with Claude Code" appears as a quick-fix action for diagnostics and failed tests; "Resolve Merge Conflicts" appears on conflicted files in the Source Control view; "Add to Chat" is available for changed files. (5) **`claude doctor` API connectivity** — the diagnostic command now reports whether the API endpoint is reachable, with the HTTP status or error message. Useful for debugging gateway/proxy misconfigurations. (6) **Upcoming Nov 30 change** — plugin marketplaces in managed `extraKnownMarketplaces` will auto-update by default. To opt a marketplace out, add `"autoUpdate": false` to its entry now, before November 30.
**Affects you if:** You run Claude Code on Amazon Bedrock, GCP Agent Platform, Microsoft Foundry, or Claude Platform on AWS; you have OTEL instrumentation and care about prompt cache cost attribution; you author or deploy plugins with optional features; you debug Claude Code connectivity issues.
**Adoption effort:** Quick (enable Code Mode in /config; update OTEL dashboards; set autoUpdate: false for any marketplace before Nov 30 if you don't want auto-updates).
**Primary source:** https://code.claude.com/docs/en/changelog (v2.1.331, Nov 23 entry — fetched directly)

### [NOTABLE] Pydantic AI v2.73.0 — sub-agent deferred tool call forwarding, E2BSandbox idle_timeout, DeprecatedModelWarning
**Source:** GitHub Releases | **Date:** 2026-11-23 | **Link:** https://github.com/pydantic/pydantic-ai/releases/tag/v2.73.0
**What changed:** Sub-agents can now pass deferred tool calls up to the caller (enabling a child agent to surface a tool call that the parent orchestrator handles); `E2BSandbox` gains `idle_timeout`; `RealtimeSession.append_voice_instructions` and a custom-voice option for GPT-Live were added; a `DeprecatedModelWarning` fires on requests to any Anthropic or OpenAI deprecated model. Breaking: `openai` package minimum floor raised to 3.50.0.
**TL;DR:** Pydantic AI v2.73.0 ships deferred tool call forwarding from sub-agents (new multi-agent orchestration pattern), E2B sandbox idle timeout control, and a deprecation warning for stale model IDs — with an `openai>=3.50.0` floor that may break pinned dependencies.
**Developer signal:** (1) **openai floor** — if you use pydantic-ai with the `openai` extra and have `openai<3.50.0` pinned in your requirements, upgrade before updating pydantic-ai or the install will fail. Run `pip install "openai>=3.50.0"` or update your lockfile. (2) **SubAgents deferred tool calls** — a sub-agent can now yield a `DeferredToolCall` back to its parent orchestrator, letting the parent handle tool calls that require higher-privilege access or cross-agent context. This is useful in multi-agent pipelines where inner agents shouldn't have direct tool access. The pattern is documented in the pydantic-ai multi-agent guide. (3) **DeprecatedModelWarning** — if you have hardcoded model IDs (e.g., `claude-opus-4-5`, `gpt-4-turbo-2024-04-09`), you'll now get a warning at request time rather than a silent success. Treat these warnings as action items — they precede errors after the retirement date. (4) **E2BSandbox idle_timeout** — if you use pydantic-ai's E2B integration, you can now set how long the sandbox remains alive with no activity before it's torn down, controlling cost on long-idle agent workflows.
**Affects you if:** You use pydantic-ai with the `openai` extra and have a pinned openai version; you build multi-agent pipelines where inner agents need to surface tool calls to orchestrators; you use pydantic-ai's E2B sandbox integration.
**Adoption effort:** Moderate (update openai dependency to >=3.50.0; test multi-agent pipelines for DeferredToolCall behavior changes; treat new DeprecatedModelWarnings as migration tasks).
**Primary source:** https://github.com/pydantic/pydantic-ai/releases (v2.73.0, Nov 23 — fetched directly)
