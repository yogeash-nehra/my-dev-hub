## 🏆 Repo of the Day

### atuin-sh/atuin — searchable, encrypted, cross-device shell history that doesn't get lost when you clear your terminal

**Link:** github.com/atuin-sh/atuin | **Stars:** ~23k (steady growth) | **Language:** Rust | **License:** MIT
**The problem:** Your shell history is a flat, lossy text file: shared across sessions, capped at a low limit, and gone whenever it scrolls off or you clear it. On a machine running coding agents and repeated tool invocations, you lose the exact command that worked an hour ago.
**Why it's today's pick:** A day with no fresh rising dev tools is the right moment to surface something from the watchlist that deserves more attention. Atuin replaces the `~/.bash_history` / `~/.zsh_history` flat file with a local SQLite database, then optionally syncs it (encrypted, E2E) across machines. Every command gets a timestamp, CWD, exit code, and duration — so `Ctrl-R` becomes a real search interface, not a linear scroll. For developers working with coding agents across multiple terminals and machines, the "why did that work last week" question becomes answerable.
**Try it in 60 seconds:**
```bash
# Install (one-liner — macOS, Linux, WSL)
curl --proto '=https' --tlsv1.2 -LsSf https://setup.atuin.sh | sh

# Restart shell, then search history:
atuin search kubectl
# Or press Ctrl-R to open the interactive UI

# Check your full history with timing info:
atuin history list --cmd-only --limit 50
```
**Instead of:** Hitting `Ctrl-R` and scrolling through a flat file, grepping `~/.bash_history`, or losing the command that worked in a throwaway session.
**Watch out for:** The sync server (`atuin.sh/sync`) requires an account for cross-device sync. You can self-host the sync server (`atuin-sh/server`) if privacy is a concern. Shell startup overhead is minimal (~1ms) but non-zero — worth checking on machines where startup time matters.

## [BREAKING] Breaking Changes

### [BREAKING] Claude Code v2.1.299 — MCP permission rules tightened: `mcp__server` no longer matches other servers' names; MCP HTTP redirects removed; sandbox security hardened
**Source:** anthropics/claude-code GitHub Releases | **Date:** October 14, 2026 | **Link:** https://github.com/anthropics/claude-code/releases/tag/v2.1.299

**What changed:** Previous versions matched MCP permission rules permissively — `mcp__a` in a permission entry could implicitly allow servers whose names contained `a` as a segment (e.g., `a__b`). v2.1.299 changes this: **allow rules now reach only the server they explicitly name**. In addition, MCP connections over HTTP no longer follow HTTP redirects (connector redirects unaffected), and the default MCP protocol version for cloud/Remote Control connectors is now `2026-07-28` (opt out with `MCP_PROTOCOL_NEGOTIATION=legacy`). Tool descriptions from Anthropic first-party MCP servers at `api.anthropic.com` are no longer truncated at 4,096 characters.

**TL;DR:** Claude Code v2.1.299 (Oct 14) makes MCP permission scoping strict-by-default, removes HTTP redirect following from MCP transports, upgrades default protocol negotiation to `2026-07-28`, and ships ~15 sandbox security fixes — any project relying on loose MCP permission wildcards will silently break.

**Developer signal:** **Audit your `settings.json` and `.claude/settings.json` today.** Look for any `allowedTools`, `mcpServers`, or permissions entries containing `mcp__<name>` patterns. Under the old behavior, `mcp__myserver` in a permission rule could match `myserver__tool` or `myserver_other` via substring logic. After v2.1.299, it only matches the server literally named `myserver`. To match all tools on a server, you must now use `mcp__<server>__*` with the full normalized server name. The protocol upgrade to `2026-07-28` is opt-out (`MCP_PROTOCOL_NEGOTIATION=legacy`), but any MCP server that doesn't support the newer protocol version will need to be tested. The HTTP redirect removal is a security hardening measure — if your MCP server relies on HTTP redirects for load-balancing or routing, you'll see connection failures. Separately, multiple sandbox security fixes close real attack surfaces: glob rules with braces/parentheses/backslashes were being parsed differently by Claude Code's policy checker vs. the actual sandbox (meaning intended-deny rules weren't enforced), and `allowRead`/`allowWrite` globs weren't re-checked when their base directory was replaced by a symlink. These were exploitable by a malicious tool or sandboxed command.

**Affects you if:** You run Claude Code with any MCP servers configured; you use `settings.json` permission rules with `mcp__` prefixes; you have MCP servers behind HTTP redirecting proxies; you run Claude Code in a sandboxed environment with glob-based allow/deny rules; you run v2.1.296–v2.1.298 and have cloud sessions (regression fixed in this release where approved tool calls ran twice).

**Adoption effort:** Moderate — permission rule audit required for any MCP setup; test MCP server compatibility with `2026-07-28` protocol version before upgrading in production.

**Primary source:** https://github.com/anthropics/claude-code/releases/tag/v2.1.299

### Claude Code's idle compaction signals that session length, not raw context size, is the new bottleneck
**Source:** Claude Code v2.1.299 release notes | **Date:** October 14, 2026 | **Link:** https://github.com/anthropics/claude-code/releases/tag/v2.1.299

**What's happening:** Claude Code v2.1.299 introduces automatic idle compaction: a conversation of 200K+ tokens left idle for ~54 minutes is compacted before its one-hour prompt cache expires, so the next message doesn't reprocess the full context. This is the second session management feature added in recent releases (idle compaction follows the `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` env var added in v2.1.290). The pattern: sessions are now long enough and rich enough that cache expiry is a real operational cost, not a theoretical edge case.

**Why watch this:** Context windows are no longer the bottleneck — session management is. Anthropic is shipping tooling to mitigate the cost of very long sessions automatically. This is worth watching because it suggests future Claude Code releases will increasingly focus on session lifecycle management: when to compact, when to archive, how to resume without losing state across hours-long agent runs.

**[BUILDER'S ANGLE] Claude Code v2.1.299's `$.prompt.media` hook enables permission-aware document review mods that weren't possible before**
The v2.1.299 mods API adds `$.prompt.media`: a `prompt.submit` hook can now read the bytes of attached images or documents before they're sent to the model. The new combination — media bytes + identity — opens up a class of enterprise compliance mods (DLP, document-type enforcement, org-specific redaction) that weren't achievable in the existing hooks API. Worth prototyping if you run Claude Code in a managed enterprise environment.
*Grounded in: Claude Code v2.1.299 (Oct 14): `$.prompt.media` (a `prompt.submit` hook reads attached image/document bytes) + `$.session.identity()` (sign-in state, org, email when managed) — both Added in this release*
