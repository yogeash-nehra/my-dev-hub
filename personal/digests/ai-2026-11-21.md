**Link:** github.com/Tencent/LoopForge | **Stars:** ~5.5k (↑ ~484 in one day, trending week of Nov 16–22) | **Language:** Go | **License:** MIT
**The problem:** A coding agent (Claude Code, Codex, Cursor CLI, etc.) running autonomously can skip planning, testing, or review steps — there is no open-source layer that enforces standard operating procedures and human approval gates across multiple agent CLIs.
**Why it's today's pick:** LoopForge supports all ten major coding-agent CLIs in a single orchestration layer: CodeBuddy, Codex, Claude Code, OpenCode, Cursor CLI, Antigravity, Kimi Code, Pi, DeepSeek Harness, and ZCode. Each workflow is defined as a named SOP with separate roles, sandboxes, and configurable human approval checkpoints — meaning you can require a human sign-off before the agent runs `git push`, or audit every planning step across runs. With Claude Code's 30-day loop limit shipping today and enterprise sign-in now supported, LoopForge fills a real gap: multi-agent governance for teams running Claude Code (or Codex, or Cursor CLI) in production. At 5,500 stars with 766 forks and a week of strong trending, it is early but not vaporware.
**Try it in 60 seconds:**
```bash
git clone https://github.com/Tencent/LoopForge.git
cd LoopForge
./start.sh  # checks for Docker, Compose, Python 3, curl and installs missing deps
# → open the printed URL, create an admin account, configure your first agent (Claude Code or Codex)
# → define a workflow SOP: plan → sandbox → review → human-approve → push
```
**Instead of:** Manually babysitting agent runs or writing bespoke orchestration scripts per agent CLI, with no enforcement of review or approval steps.

### [MEDIUM] Claude Code v2.1.330 — Easel mod, enterprise sign-in, 30-day loops, max_tokens retry restored
**Source:** Claude Code Changelog | **Date:** 2026-11-20 | **Link:** https://code.claude.com/docs/en/changelog
**What changed:** v2.1.330 ships the Easel mod (built-in chart drawing), enterprise sign-in via the Admin Console, 30-day scheduled task / `/loop` limits (up from 7 days), self-hosted runner `--start-dir` and two new `/metrics` gauges, and VS Code `/fork` / `/workflows` support. It also reverts v2.1.329's removal of the `max_tokens` automatic retry.
**TL;DR:** Claude Code v2.1.330 adds chart visualization (Easel mod), enterprise org auth, and extends autonomous task loops to 30 days — plus restores the `max_tokens` auto-retry that yesterday's v2.1.329 had removed, making yesterday's gateway-deployment migration guidance moot.
**Developer signal:** (1) **`max_tokens` auto-retry is BACK** — v2.1.329 removed the automatic retry when requests hit a gateway output-token cap, and yesterday's digest recommended setting `CLAUDE_CODE_MAX_OUTPUT_TOKENS` as a workaround for Bedrock/GCP/Foundry gateway deployments. v2.1.330 reverts this change. If you set that env var as a mitigation in the last 24 hours, it is no longer required. Remove it if the lower output cap was not your intent. (2) **Easel mod** — available on Pro, Max, and (where available) Team and Enterprise on macOS and Linux. It draws charts on request ("plot this data") and automatically under MCP metrics results. To disable automatic chart generation: open `/config` and toggle the Easel automatic-charts setting. The mod is built-in, no install needed. (3) **Enterprise sign-in** — `claude auth login` now applies the organization's settings and cloud provider/gateway configuration automatically. This is the key primitive for Enterprise Admin Console fleet management; previously, org settings were applied separately from the sign-in flow. (4) **30-day task limit for scheduled tasks and `/loop`** — tasks created before v2.1.330 still end at 7 days; only tasks created after the update get the 30-day window. If you have running scheduled tasks, they retain the old limit until recreated. (5) **VS Code additions**: `/fork`, `/workflows`, and three new settings (`claudeCode.escapeStopsClaude`, `claudeCode.pinPrompt`, `claudeCode.contextUsageThreshold`). (6) **Stricter `rm` safety** — more `rm` commands targeting root, home, top-level folders, or the working folder now require approval. Review any automation scripts that issue broad `rm` commands if you rely on non-interactive mode. (7) **`deniedMcpServers` name matching** changed: name entries now hide only the named claude.ai connector; to block all connectors at a URL, deny the exact URL — if you have connector blocking configured by name, verify it still works as intended. (8) **Code Mode PreToolUse hook behavior revert note**: the `"onFailure": "block"` opt-in from v2.1.329 is still present; v2.1.330 did not revert that hook change.
**Affects you if:** You deployed the `CLAUDE_CODE_MAX_OUTPUT_TOKENS` workaround from yesterday's digest; you use Claude Code on Pro/Max/Enterprise (Easel mod); you manage an Enterprise org and want seamless gateway routing; you run scheduled tasks or `/loop` routines longer than 7 days; you use automation scripts with `rm` commands; you have `deniedMcpServers` configured by name.
**Adoption effort:** Quick (update Claude Code, remove `CLAUDE_CODE_MAX_OUTPUT_TOKENS` env var if set, verify `deniedMcpServers` config if you use it; Easel is opt-out not opt-in).
**Primary source:** https://code.claude.com/docs/en/changelog (v2.1.330, Nov 20 entry — fetched directly)

Useful for: agent-to-agent encrypted data channels, CI artifact piping between runners, or secure local service exposure without ngrok or Cloudflare Tunnel.
