## [BREAKING] Breaking Changes

### [BREAKING] E2B SDK 2.62.0 — file write streaming overhaul, retainOutput option, JS stream buffering removed
**Source:** GitHub Releases (e2b-dev/E2B) | **Date:** 2026-10-28 | **Link:** https://github.com/e2b-dev/E2B/releases/tag/e2b%402.62.0
**What changed:** `files.write` now streams byte-chunk iterables directly to the sandbox instead of buffering them in memory. Three breaking behavioral changes shipped alongside this in JS and Python.
**TL;DR:** E2B 2.62.0 makes large file writes memory-efficient via streaming, but breaks any JS code that combined gzip with non-octet-stream uploads, ran file writes in Firefox/Safari, or relied on stream buffering — and adds a new `retainOutput` option to command execution.
**Developer signal:**
- **Highest priority — gzip + octet-stream combo:** If your code passes `gzip: true, useOctetStream: false` (JS) or `gzip=True, use_octet_stream=False` (Python), it now throws `InvalidArgumentError` / `InvalidArgumentException` instead of silently gzip-overriding. Pick one: either keep `gzip` and let it default to octet-stream, or drop gzip. Do this before upgrading.
- **Browser code (Firefox, Safari, iOS):** `ReadableStream` and `AsyncIterable` file writes now throw in browsers without streaming request body support. Convert to `Blob` first: `await new Response(stream).blob()`. Chromium-based browsers continue to stream fine.
- **Check envd version:** Stream uploads require envd 0.5.7+ in your sandbox template. Older envd throws `TemplateError`. If you manage your own templates, update envd before deploying SDK 2.62.0.
- **Python async/sync iterable types:** `Iterable[bytes]` works only in `Sandbox` (sync); `AsyncIterable[bytes]` works only in `AsyncSandbox` (async). Mixing types throws `InvalidArgumentException`.
- **New `retainOutput=False`:** For high-volume or long-running commands where buffering all stdout/stderr is costly, set `retain_output=False` and handle output exclusively via `on_stdout`/`on_stderr` callbacks. Callbacks still receive all output even with buffering off.
**Affects you if:** You use the `e2b` JS or Python SDK with `files.write`; you upload files into E2B sandboxes from browser contexts (Firefox, Safari, iOS); you use `gzip` combined with `useOctetStream: false`; you have long-running commands where buffering command output wastes memory.
**Adoption effort:** Moderate (audit `files.write` call sites, fix gzip+octet-stream combinations, add Blob conversion for browser code; straightforward once you know the patterns).
**Primary source:** https://github.com/e2b-dev/E2B/releases/tag/e2b%402.62.0

## API & SDK Changes

### [MEDIUM] Anthropic Usage and Cost Analytics API (beta) — new programmatic spend reporting replaces legacy usage/cost API
**Source:** Anthropic Platform Release Notes | **Date:** 2026-10-29 | **Link:** https://platform.claude.com/docs/en/release-notes/overview
**What changed:** Two new API endpoints launched in beta under the `analytics-usage-cost-2026-08-24` beta header: `/v1/organizations/analytics/usage` (token counts and request counts) and `/v1/organizations/analytics/cost` (spend in USD). Simultaneously, the existing Usage and Cost API and the Claude Enterprise Analytics API's `usage_report`, `cost_report`, `user_usage_report`, and `user_cost_report` endpoints were designated **legacy** — still supported, migration guides provided.
**TL;DR:** The new analytics API lets organizations filter and group usage/cost data by model, workspace, API key, actor (specific user or service account), and time granularity (daily, hourly, per-minute), replacing two legacy reporting APIs.
**Developer signal:** If your organization calls the old Usage and Cost API or Claude Enterprise Analytics endpoints programmatically, begin migration: read the "Migrate from the Usage and Cost API" and "Migrate from the Claude Enterprise usage and cost reports" guides linked from the new API docs. No forced retirement date is announced yet — "legacy" status precedes retirement, but the timeline isn't public. To use the new API directly, add the `anthropic-beta: analytics-usage-cost-2026-08-24` header; the Anthropic SDK and `ant` CLI send this automatically. The most significant capability upgrade is **actor-level filtering**: you can now see exactly which user or service account consumed tokens, enabling per-user quota enforcement and cost attribution at the API layer. Time-series buckets (daily, hourly, per-minute) make it straightforward to build spend dashboards directly from the API rather than exporting from the Claude Console.
**Affects you if:** You use the old Anthropic Usage and Cost API or Claude Enterprise Analytics API programmatically; you build multi-tenant Claude applications and want native per-actor usage tracking; you need time-series billing data from the API rather than the Console UI.
**Adoption effort:** Moderate (update API call sites to new endpoints and beta header; migration guides are provided; old endpoints remain supported during the transition).
**Primary source:** https://platform.claude.com/docs/en/manage-claude/usage-cost-analytics-api

## Tooling

### [NOTABLE] Agno v3.1.12 — native approval routing for Claude Code and Codex permission requests in AgentOS
**Source:** GitHub Releases (agno-agi/agno) | **Date:** 2026-10-29 | **Link:** https://github.com/agno-agi/agno/releases
**What changed:** `ClaudeAgent` and `CodexAgent` permission requests now surface in the AgentOS approval UI and pause the run until a human approves or rejects. Previously, `CodexAgent` with no approval settings would let requests go unanswered; v3.1.12 changes the default to the `on-request` policy, bounding the pause with `hitl_timeout` (default: 900 seconds). Routines can now be created with `enabled=False` and activated later from the UI without redeployment. `ChartTools.create_chart()` gains an optional preformatted headline value shown beside the chart title. Bug fixes include: FastAPI tracing no longer polluting Agno traces, routine cancellations recorded only after the run stops, and `AccuracyEval`'s default judge updated from the retired `o4-mini` to `gpt-5.6-terra`.
**TL;DR:** Agno v3.1.12 makes Claude Code and Codex permission requests pause inside AgentOS for human approval by default — the first agent framework to route HITL approval for both agents natively through a single UI.
**Developer signal:** If you run `ClaudeAgent` or `CodexAgent` in Agno, the default behavior changes: runs now pause at permission request checkpoints and wait up to 900 seconds for approval. Review your `hitl_timeout` setting — for agents that frequently trigger permission requests in production, 15 minutes per checkpoint may be too long (or you may want this as a safety gate). The initially-disabled routines feature is useful for setting up scheduled agent jobs you want to validate before going live: create with `enabled=False`, test manually, then flip the switch from the AgentOS UI.
**Affects you if:** You use Agno's AgentOS with `ClaudeAgent` or `CodexAgent`; you run agents that trigger Claude Code or Codex permission requests; you build scheduled automations in Agno Routines.
**Adoption effort:** Quick (upgrade Agno; review `hitl_timeout` if agents trigger frequent approval requests; no code changes required).
**Primary source:** https://github.com/agno-agi/agno/releases

**Source:** Agno v3.1.12 | **Date:** 2026-10-29 | **Link:** https://github.com/agno-agi/agno/releases
**What's happening:** Agno v3.1.12 ships approval routing for Claude Code and Codex as a framework default — changing the default from "requests go unanswered" to "runs pause for human approval." This follows Claude Code's own `ultrareview` workspace-trust requirement (Oct 21), Anthropic's audit log expansion, and E2B's `retainOutput` pattern for surfacing command output without buffering it all. Each of these is a different mechanism for giving humans visibility or control over what agents do, without requiring teams to build the instrumentation themselves.
**Why watch this:** If HITL tooling continues maturing at this pace, the architectural question for agent systems changes from "how do I implement approval gates" to "which platform's approval primitives do I integrate with." Watch LangGraph and Pydantic AI for similar approval-routing primitives — if two or three major frameworks ship this as a default in Q4 2026, it becomes a baseline expectation for production agentic systems rather than a differentiator.
