### openai/codex-security — CLI + SDK that finds, validates, and patches security vulnerabilities in your codebase
**Link:** github.com/openai/codex-security | **Stars:** ~12.3k (↑ 663 today) | **Language:** TypeScript | **License:** Apache-2.0
**The problem:** Running SAST tools flags vulnerabilities but leaves you staring at findings with no patch — correlating results, deduplicating, triaging, and writing fixes is still manual work.
**Why it's today's pick:** codex-security landed as the #2 trending repo today (663 stars), and ships a complete developer workflow: `cs scan .` finds vulnerabilities, `cs investigate` validates each finding (filtering false positives), and `cs patch` generates and verifies fixes. It exports to SARIF, JSON, and CSV, and integrates with Linear, Jira, and GitHub — meaning findings can go directly into your existing triage workflow without a separate import step. The GitHub Action wrapper makes it straightforward to add to CI: drop in the example workflow, add the API key, set a spend cap, and your weekly or PR-triggered scan is live.
**Try it in 60 seconds:**
```bash
npm install --global @openai/codex-security
cs login
# Full repo scan
cs scan .
# Scan only changed files against main
cs scan . --diff origin/main --mode deep
```
**Instead of:** Running Semgrep or Snyk without automatic patch generation — those flag vulnerabilities but require a manual remediation loop; codex-security generates a patch and verifies it in one pass.
**Watch out for:** Some scan capabilities (labeled "Trusted Access for Cyber") appear to require a specific OpenAI access tier — unclear from the README exactly what that gate is; check before integrating into a critical pipeline. Releases are tracked through npm / CHANGELOG rather than GitHub Releases tags, so the GitHub releases page shows nothing. Node.js 22.13.0+ required (also supports 24.x and 26.x).

## API & SDK Changes

### [HIGH] Anthropic Self-Hosted Managed Agents — run the full Managed Agents service on your own infrastructure
**Source:** Anthropic Platform Release Notes | **Date:** 2026-11-12 | **Link:** https://platform.claude.com/docs/en/release-notes/overview
**What changed:** Previously, Managed Agents had one self-hosting option — self-hosted sandboxes, where you run tool execution but Anthropic runs the agent service, session storage, and agent loop. Today Anthropic launched the other end of the spectrum: self-hosted Managed Agents, where you run the entire service — the API, agent loop, agents, sessions, and session history — on your own infrastructure, while model calls go to whichever inference provider you configure.
**TL;DR:** Anthropic's Managed Agents service (`cma-server`) is now deployable on your own infra (Linux/macOS, PostgreSQL 16+), with model calls routable to Bedrock, Google Cloud (Google-managed), Microsoft Foundry, or your own model gateway instead of Anthropic's API.
**Developer signal:** To request access to the `cma-server` download, contact your Anthropic account team. Once you have access: run `cma-server` alongside a PostgreSQL 16 database; create environments with the `cma-server-admin` CLI; run workers with `ant beta:worker poll` or the Python/TypeScript/Go SDK workers. Your applications and the `ant` CLI connect to your server's URL rather than `api.anthropic.com` — the API surface is identical, so existing code requires only a URL change. The inference credential (the API key / cloud credential your server uses for model calls) lives only in `cma-server`'s config — it never reaches your applications or workers. Sandbox platform providers (Cloudflare, Daytona, E2B, Modal, Vercel, AWS Lambda, Fly.io, GKE) have published guides for running workers on their platforms. Important limitations: self-hosted Managed Agents is not eligible for ZDR (Zero Data Retention), does not support HIPAA, and some features available on the hosted service differ (see the [Differences from the hosted service](https://platform.claude.com/docs/en/managed-agents/self-hosted/differences) page). The agent's `bash` tool runs with the worker process's permissions — isolation is your responsibility; run workers in disposable containers or VMs.
**Affects you if:** You build Managed Agents-based products and need agents, sessions, or session history stored on infrastructure you control; you need model calls routed to Amazon Bedrock, GCP (Google-managed), Microsoft Foundry, or your own gateway; your compliance requirements require data-residency guarantees that Anthropic's hosted service cannot provide.
**Adoption effort:** Significant (stand up `cma-server`, configure PostgreSQL, generate environment keys, wire an identity provider for the console, run workers in isolated sandboxes)
**Primary source:** https://platform.claude.com/docs/en/managed-agents/self-hosted

## Tooling

### [MEDIUM] PydanticAI v2.68.0 — ConversationStore, GoogleDecisionsModel, in-run RequestInput, Temporal cancellation
**Source:** GitHub (pydantic/pydantic-ai v2.68.0) | **Date:** 2026-11-11 | **Link:** https://github.com/pydantic/pydantic-ai/releases/tag/v2.68.0
**What changed:** v2.67.0 → v2.68.0: adds ConversationStore for loading/saving UI adapter conversations across sessions; adds `GoogleDecisionsModel` backend for the Gemini Decisions API; adds `RequestInput` to pause a durable run and request approval or answers from a user mid-run; adds Temporal cancellation via a workflow signal; adds `RefineOutput` harness capability; enables SubAgents Temporal and DBOS child workflow delegation. Compatibility notes include renamed sub-agent event fields (adding `Event` suffix, with deprecated aliases kept) and harness parameter renames (`num_results` → `max_results`, `max_duration_secs` → `max_duration_seconds`, deprecated aliases kept). Also includes ~20 bug fixes covering model ID resolution, `AnthropicModel.count_tokens` sending betas, max_tokens clamping for Claude models, and compaction reporting.
**TL;DR:** PydanticAI v2.68.0 adds `ConversationStore` for persistent UI conversations, `GoogleDecisionsModel` for Google's new Gemini Decisions API, `RequestInput` for in-run human-in-the-loop approval, and Temporal workflow signal cancellation.
**Developer signal:** `pip install --upgrade pydantic-ai` to get v2.68.0. For ConversationStore: instantiate with `ConversationStore(backend=...)` and call `store.load_conversation(session_id)` to restore past UI adapter conversations into a new run — useful for resuming agent sessions with a history. For GoogleDecisionsModel: pass `model='gemini-decisions-1'` or instantiate `GoogleDecisionsModel()` directly — this requires a Gemini API key and targets Google's new Decisions API. For RequestInput: add `RequestInput` to your SubAgent task config to pause execution and prompt the user for a decision before proceeding; `answered_by` on the deferred call tracks who answered. The renamed event fields use deprecated aliases — existing code will continue to work but will log deprecation warnings; update `num_results` to `max_results` and `max_duration_secs` to `max_duration_seconds` before the aliases are removed in a future release. The `ModelFallback` behavior change (now moves to the next model when output hits `max_tokens`) may affect agents relying on partial truncated output from a fallback model — test your fallback chains.
**Affects you if:** You use PydanticAI as your agent framework with Temporal or DBOS durable execution; you want to integrate Google's new Gemini Decisions API; you build multi-turn UI adapter conversations that need to persist across sessions; you rely on `ModelFallback` with any `max_tokens`-limited provider.
**Adoption effort:** Quick for most features (drop-in upgrade); Moderate if you use renamed harness params or SubAgent event fields that now have deprecated aliases
**Primary source:** https://github.com/pydantic/pydantic-ai/releases/tag/v2.68.0

## Trends & Emerging Tech

### Self-hosted infrastructure tiers for Managed Agents are now complete — Anthropic offers cloud, hybrid, and full self-hosted
**Source:** Anthropic Platform Release Notes | **Date:** 2026-11-12 | **Link:** https://platform.claude.com/docs/en/managed-agents/self-hosted
**What's happening:** Anthropic now offers three infrastructure tiers for Managed Agents: (1) full cloud — Anthropic hosts everything; (2) self-hosted sandboxes — you host tool execution, Anthropic runs the agent loop and storage; (3) self-hosted Managed Agents — you host everything including the agent loop, storage, and inference routing. This completes a spectrum that many enterprise agentic platforms (LangChain, Microsoft AutoGen, OpenHands) have supported in some form, but which Anthropic's Managed Agents had not yet. The launch also reveals the deployment model: a `cma-server` Go/binary that connects to PostgreSQL, runs the agent loop, and calls whatever inference provider you configure — structurally similar to how teams self-host LangGraph Cloud or OpenHands Server today.
**Why watch this:** The pattern to track is whether this sparks operator-layer competition. E2B, Daytona, Cloudflare, Vercel, and Modal all already have self-hosted sandbox guides on Anthropic's docs — now they also have a path to become full Managed Agents hosting providers. A team that needs both compute isolation and storage residency no longer needs to choose between Anthropic's service and their own infra. The enterprise compliance story for Managed Agents just became much stronger, which likely accelerates its adoption in regulated industries.
